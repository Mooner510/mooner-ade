# 테스트 실행 안내

현재 결과는 [VERIFICATION](VERIFICATION.md)에서 확인하세요. 모든 명령은 저장소 루트에서 실행합니다.

## 설치와 자동 검사

```sh
pnpm install --frozen-lockfile
pnpm check   # 웹 타입 검사 + Node 테스트
pnpm audit
```

`check`는 `pnpm typecheck`(웹 UI 타입 검사)와 `tests/*.test.mjs`를 실행합니다. 테스트는 임시 저장소·데이터 폴더·가짜 Codex app server를 사용하며 모델을 호출하지 않습니다. 로컬 서버 테스트에는 실제 Git·PTY 호출이 포함됩니다. 제거한 API(`files/read`·`files/save`·`files/search`, `git/commit`, SDK 실행 등)가 404를 반환하는지도 확인합니다(채팅 `@` 언급용 `files/list`는 제거 대상이 아닙니다).

파일 감시 오류를 집중 확인하려면 `node --test tests/project-watch.test.mjs`를 실행합니다. 생성 실패, 비동기 EMFILE, 경로 배치 상한, 정상 종료 후 지연 이벤트 차단을 검증합니다.

## UI E2E

```sh
pnpm e2e
# Chrome을 찾지 못하면:
CHROME_PATH=/path/to/chrome pnpm e2e
```

`e2e`는 웹 UI를 빌드한 뒤 로컬 서버와 격리된 headless Chrome으로 앱 창과 같은 화면을 띄웁니다. 임시 홈·프로젝트·앱 데이터·Chrome 프로필을 만들고 종료 시 정리합니다. 모델 호출 없이 접속 인증, 토큰 URL 제거, 프로젝트 열기, 실제 PTY 입력과 파일 쓰기, 스크롤백 복원, 에이전트 상태 보고, Git Diff 렌더링, 탭 추가·새로고침 복원을 확인합니다. 같은 Chrome에서 사이드바 네이티브 드래그 테스트도 실행합니다. 페이지 예외·console.error가 있으면 실패합니다. Electron 셸(창·메뉴·폴더 선택)은 이 검사의 범위가 아닙니다.

`pnpm check`에서 사이드바 드래그 테스트가 건너뛰어지는 것은 `ADE_TEST_CDP`가 없기 때문입니다. `pnpm e2e`가 Chrome을 시작하고 해당 테스트에 주소를 전달합니다.

`pnpm e2e`(`scripts/e2e.mjs`)의 확인 범위는 위에 적은 것까지입니다. 채팅(질문 카드·서브에이전트·계획 검토·이미지 첨부 등), 피드백 요청, 인터랙티브 UI(`ade-ui` 프레임), 설정 화면, Electron 셸(`ade:capture`, 업데이트·플러그인 확인 창)은 이 스크립트가 다루지 않습니다(스크립트에 해당 화면을 여는 단계가 없음). 이 영역은 아래 수동 절차와 `tests/*.test.mjs` 단위 테스트로 확인해야 하며, `pnpm e2e`가 통과해도 그 확인을 대신하지 않습니다.

Claude pane을 여러 개 띄우면 각 pane 헤더에 자기 대화 기준 타이머가 따로 뜨고, `/clear` 직후·Claude 종료·SSH 안의 Claude에서는 타이머가 사라져야 합니다. 사이드바에서는 지금 보고 있지 않은 탭(분할 탭은 각 pane 줄)의 오른쪽 끝에만 같은 타이머가 작게 뜨고, 그 탭을 선택하면 사이드바에서 사라지는지, 알림 점·닫기 버튼과 겹치지 않는지 확인.

- 캐시 만료 전송 경고(`node --test tests/claude-cache-warning.test.mjs tests/ai-settings.test.mjs`로 판정부터 확인): 설정 > AI 툴 > Claude Code에서 "캐시 만료 시 전송 경고"가 기본 켜짐이고 기준 시간 10분인지. 1시간 캐시의 Claude pane에서 캐시가 식었거나 남은 시간이 기준 이하일 때 메시지를 쓰고 Enter를 누르면 보내기 전에 "프롬프트 캐시가 … 보낼까요?" 선택창이 뜨고, 첫 항목 "취소"가 선택된 상태인지(Enter 한 번 더로 보내지지 않음). 취소·Esc 후에는 메시지가 전송되지 않고 입력한 글이 그대로 남아 있는지, "그래도 보내기"를 고르면 그대로 전송되는지. 한글 IME 조합 중 Enter, 선택창이 떠 있는 동안 키 입력, 선택창을 닫은 뒤 터미널 포커스. 슬래시 명령(`/clear`)·`@` 자동완성 선택·빈 입력·권한 대화상자·작업 중(Esc 전 Enter)에는 뜨지 않는지, 5분 캐시 계정은 완전히 식었을 때만 뜨는지. "지금 업데이트"는 진행 중인 작업을 보여주고 중단해도 괜찮다고 할 때만 바로 설치하는지, 취소하면 설치하지 않는지. 한가할 때 "지금 업데이트"를 고른 뒤 받는 중 작업이 시작되면 같은 확인을 다시 하는지. 설정의 업데이트 확인 버튼이 받아 둔 업데이트에 대해 "지금 재시작/받지 않기/종료할 때까지 대기"를 보여 주는지, "나중에"를 고른 버전은 10분 뒤에 자동으로 다시 묻지 않는지(앱 재시작 후에는 다시 물음). 업데이트 뒤 `%TEMP%`에 `mooner-update-*` 폴더가 남지 않는지(Windows는 헬퍼가 몇 초 뒤 지움), 설치 폴더에 이전 버전 사본이 없는지.

2. 창을 좁혀도 팝오버가 화면 밖으로 나가지 않는다. 사용량 색상을 끄면 막대·% 색이 단색이 된다. 라이트 테마에서도 읽힌다.

## 사용량 조회의 .envrc 적용

1. `.envrc`에 `export CLAUDE_CONFIG_DIR="$HOME/.claude-work"`가 있는 프로젝트에서 `direnv allow` 상태로 열고 터미널에 에이전트를 띄우지 않는다 → 상태바 Claude 사용량 팝오버의 계정이 `~/.claude-work (프로젝트 .envrc 기준)`이고, 그 계정의 요금제·사용률이 보인다.
2. 같은 프로젝트를 `direnv deny`(또는 `.envrc`를 고쳐 다시 blocked가 된 상태)로 바꾼다 → `.envrc`가 활성이 아니므로 계정이 `앱 환경`(또는 실행 중인 에이전트)으로 돌아가고 `.claude-work`로 조회하지 않는다. `direnv allow` 후 약 60초 안에 다시 `.envrc` 기준으로 바뀐다.
3. 터미널에 `~/.claude`로 실행 중인 에이전트가 있어도 allow된 `.envrc`가 계정을 정하면 그 계정으로 조회한다. `.envrc`가 없거나 계정을 정하지 않으면 실행 중인 에이전트의 계정을 따른다.
4. `node --test tests/usage.test.mjs`.

9. 스티어링·팔로업: 응답 중 입력창에서 Enter → 메시지가 점선 테두리의 '스티어링 · 대기 중 · Esc로 취소' 말풍선으로 응답 진행 표시(생각 중/도구 카드) **아래**에 붙는다(위로 올라가지 않는다). CLI가 그 메시지를 받아들이면 일반 사용자 말풍선으로 바뀌고 응답에 반영된다(예: 긴 Bash 실행 중 "답에 STEERED를 덧붙여줘"). 대기 중에 Esc → 말풍선이 사라지고 문구가 입력창에 돌아오며(입력창이 비어 있을 때만) 응답은 중단 없이 계속되고 그 메시지는 처리되지 않는다. 대기 중인 스티어링이 없을 때의 Esc는 기존처럼 응답을 중단한다. Tab → 응답이 끝난 뒤 보내는 팔로업 대기열(설정의 follow-up 큐가 켜진 경우).
10. Cursor 하단 옵션 즉시 변경: Cursor 채팅에서 응답이 진행되는 중에도 권한 모드·모델·Fast·Effort·MAX·Bypass(Run Everything)를 눌러 잠기지 않고 **누른 즉시** 표시가 바뀐다("응답 후 변경 가능" 문구 없음). 서버가 거부하면 원래 값으로 되돌아가고 오류가 보인다. Bypass를 켜면 대기 중이던 권한 요청도 자동 허용되고, 끄면 다시 묻는다. 샌드박스는 Cursor 재시작이 필요해 응답 중에 바꾸면 '샌드박스: 다음 응답부터 적용'이 표시되고 응답이 끝난 뒤 적용된다. 탭에 포커스가 가면 Cursor 프로세스를 미리 띄워(약 6초) 첫 변경·첫 메시지가 기다리지 않는다.
10. 진행 상태 줄: 응답 중에는 대화 맨 아래에 한 줄이 계속 자리를 지키며 문구만 바뀐다(생각하는 중… · `Bash 실행 중…` · `응답을 작성하는 중…` · `/compact 실행 중…` · 승인을 기다리는 중). 스피너(느리게 회전) · 경과 시간 · 추정 토큰이 보이고, 생각만 8초 넘게 하면 Effort 이름과 함께 글자가 빨개진다. CLI가 생각 내용 자체는 주지 않으므로 '무슨 생각을 하는지' 글은 나오지 않는다(토큰 추정치만). 턴이 끝나면 이 줄이 부드럽게 접혀 사라진다. 응답 글은 한 번에 튀어나오지 않고 부드럽게 이어서 나타난다(모션 줄이기 설정 시 즉시 표시).
11. 복사·Branch·Rewind: 응답이 끝난 턴의 마지막 어시스턴트 메시지 왼쪽 아래에 복사 · Branch · Rewind 아이콘이 항상 보인다. Branch → 그 지점까지의 대화를 가진 새 채팅 탭이 열리고(`--resume <id> --resume-session-at <uuid> --fork-session`) 이어서 물으면 그 지점까지의 맥락으로만 답한다. Rewind → 확인 후 그 메시지 아래 대화가 사라지고 '여기까지 되돌렸습니다' 안내가 나오며 다음 메시지는 그 지점부터 이어진다(되돌린 뒤 이전 내용을 물으면 모른다고 답함). 대화 기록만 되돌리며 Claude가 이미 바꾼 파일은 그대로다.
12. 권한 모드: 하단 줄의 모드 앞에 아이콘이 있다(기본 방패 · 편집 허용 편집 노트 · 계획 문서 · 자동 반짝임 · Bypass 번개). 입력창에서 Shift+Tab → 기본 → 편집 허용 → 계획 → 자동 → 기본 순으로 바뀐다. `Bypass`는 순환에 없고 드롭다운으로만 고르며, 그 상태에서 Shift+Tab이면 기본으로 나온다. 응답 중에 바꿔도 즉시 `set_permission_mode`로 CLI에 반영된다. 슬래시 메뉴가 열려 있어도 Shift+Tab은 모드 전환이다.
13. 하단 줄의 모드·모델·Effort 버튼은 가로 8px·세로 4px 여백이고, 호버하면 배경이 들어온다(닫은 뒤 키보드 포커스 때도 테두리 대신 배경). 모델 이름은 굵게 보이고 계열 색 그대로다. 모드 색은 Provider CLI와 맞춘다. Claude: 기본 회색 · 편집 허용 보라 · 계획 청록 · 자동 노랑 · Bypass 다홍. Codex: 기본 회색 · 편집 허용 청록(accent) · 계획 녹색(read-only) · Bypass 빨강. Cursor: 기본 회색 · 계획 노랑 · 질문 전용 녹색. 눌러서 열리는 메뉴는 둥근 카드에 여백·둥근 행으로 나오고, 현재 선택은 옅은 배경과 체크로 표시된다.
14. 모델 메뉴: 기본 모델(옆에 지금 가리키는 모델) · 최신 5.x 별칭과 1M 항목 · 가는 선 · `더 많은 모델…` 순이다. `더 많은 모델…`을 누르면 모달이 열리고 Claude Code가 알려주는 지원 모델 전체가 체크 표시 목록으로 나온다. 정렬은 ① Fable이 항상 맨 위(Fable끼리는 버전 내림차순) ② 나머지는 버전(5.5 → 5 → 4.8 …) 내림차순 ③ 같은 버전 안에서 Opus · Sonnet · Haiku 순이며, 컨텍스트가 1M인 Opus·Sonnet은 '긴 컨텍스트' 대신 이름 뒤에 회색 `(1M)`이 붙은 행(`Opus 5.5 (1M)`)으로 일반 모델 바로 아래에 붙는다. 하단 버튼·상태 표시줄의 모델 이름도 같은 `(1M)` 표기다. `기본 모델`을 고르면 하단 버튼이 `기본 모델`로 바뀌고(이전 모델 이름이 남지 않는다), 응답 중이 아니면 claude가 `--model` 없이 다시 시작되며(같은 세션) 응답 중이면 끝난 뒤 적용된다. 다음 응답의 init에서 실제 모델이 보고되면 그 모델 이름으로 바뀐다. `기본 모델` 옆의 모델 이름은 그 프로젝트 폴더에서 CLI가 정하는 기본값이다(프로젝트 설정의 model도 반영, 프로젝트마다 1시간 캐시). 한계: 응답 중에 기본으로 되돌리는 경로는 직접 확인하지 못했다. 현재 모델에 체크가 있고, 행을 누르면 그 모델로 바뀌며(이 채팅에만 적용), Esc·X로 닫는다. 데이터 출처: 서버가 CLI가 직접 만든 캐시 `~/.claude/cache/model-catalog/*-cc.json`에서 모델 ID·이름·계열·컨텍스트 창만 읽는다(로그인 정보·다른 필드는 읽지 않으며 값 검증 후 최대 64개). 최신성은 CLI를 쓰는 동안 약 1시간마다 CLI가 갱신하는 것을 그대로 따르므로 새 모델은 CLI가 알게 되면 반영되고, 캐시가 없으면 빠른 메뉴의 별칭 목록만 보인다. 빠른 메뉴의 버전은 서버가 별칭마다 `claude -p "/cost" --model <별칭> --no-session-persistence`를 돌려 init 이벤트의 실제 모델 ID로 얻는다(로컬 명령이라 모델 호출·비용 없음, 1시간 캐시).
15. 글꼴: Inter(UI 영문·숫자)와 Noto Sans KR(한글, Noto Sans CJK의 한국어판)을 UI 기본 글꼴로, JetBrains Mono를 코드·터미널·Monaco 기본으로 앱에 포함한다(모두 SIL OFL 1.1, 상업 사용 가능, 라이선스 문서는 빌드 결과의 `licenses/`). Mac이 아니라 Windows·Linux에서 열어도 같은 글꼴로 보여야 한다. 확인: 개발자 도구 콘솔에서 `document.fonts`의 `Inter Variable`·`Noto Sans KR Variable`·`JetBrains Mono Variable`이 loaded인지(한글이 화면에 있어야 Noto가 loaded로 바뀜) 본다. 설정에서 터미널 글꼴을 직접 지정하면 그 글꼴이 우선이고 없으면 번들 글꼴로 돌아간다. 한계: 번들 용량이 약 4.5MB 늘었다(Noto Sans KR 가변 글꼴이 글자 범위별 조각 약 120개 3.6MB이고 화면에 필요한 조각만 불러온다), 이탤릭 코드는 JetBrains Mono 이탤릭 파일을 넣지 않아 기울임으로 합성된다. Windows·Linux에서의 실제 모습은 직접 확인하지 못했다.

16. 사이드바 채팅 탭 표시: 채팅 탭 아이콘은 별표가 든 말풍선(주황)이라 파일 아이콘과 구분되고, 기울임 이름의 마지막 글자(`팅`)가 잘리지 않는다. 분할된 탭 안의 채팅 줄도 같다.

- 피드백 요청: 브라우저·데스크톱 동일 동작 (2026-11-12): **브라우저(Chrome)** 에서도 캡쳐 버튼 3개가 보이고, 캡쳐 시 브라우저의 "이 탭 공유" 허가 창 뒤 요소·범위 이미지가 올바르게 잘려 들어오는지(공유 창을 닫으면 조용히 취소). 패널이 열린 상태에서 이미지를 어디에 있든 붙여넣기(텍스트 칸 밖)·패널 위에 끌어 놓으면 열린 초안, 없으면 새 초안에 들어가는지. 설정 > 피드백의 **AI 정리 모델·Effort** 기본값이 Haiku 5.5·낮음이고 AI 정리가 `claude --model claude-haiku-5-5 --effort low`로 실행되는지. 열린 프로젝트가 없는 첫 화면 우상단 아이콘으로도 패널이 열리는지.

| 중단 직후 재전송 | 긴 응답 중 Esc로 중단한 뒤 곧바로 새 메시지를 보내도 새 응답이 끝날 때까지 상태가 `응답 중`으로 유지된다(중단 응답이 늦게 와서 새 턴을 `대기 중`으로 바꾸지 않는다) |

3. 이전 버전 설정(defaultMode 필드 없음)으로 업데이트하면 CLI 기본값을 유지한다. 활성 CLI pane에서 Claude·Codex·Cursor를 이용할 때 하단에 이미지가 있는 Chat 안내가 표시된다. 새 설치, Chat pane, 일반 셸에서는 표시되지 않는다.

## 첫 메시지 지연: MCP 연결 대기 제한 (2026-11-12)

원인: 채팅이 `--mcp-config`(에이전트 버스)로 Claude Code를 띄우면, CLI가 사용자의 다른 MCP 서버(느리거나 응답 없는 서버)가 모두 연결될 때까지 `init`을 잡고 있었다(claude 2.1.322 실측: 플래그 없음 1.1초, 있음 29.7초). ADE가 `CLAUDE_CODE_MCP_STARTUP_WAIT_MS=3000`을 넘겨 이 대기를 3초로 제한한다. Codex(시작 0.2~0.5초)와 Cursor(약 6초, 포커스 시 미리 시작)는 해당 없음.

5. 알려진 한계: 링크는 도구 결과 속 `https://claude.ai/artifact/<id>`에서 찾는다. 결과에 링크가 없는 도구는 카드가 없다. 제목은 입력의 `title`/`name`/`container.create.name`에서 가져오며 없으면 링크가 제목으로 보인다.
- 피드백 요청: 작성 화면 통합 (2026-11-12): 목록 상단에 **새 피드백** 버튼 하나만 있고, 열면 직접/AI 구분 없이 같은 화면(큰 내용 칸 → 선택 제목 칸 → 이미지 → 하단 `삭제 · 모델 · 추론 강도 · AI로 정리 · 제출`)인지. 내용만 적고 창을 닫았다가 다시 열어도(앱 재시작 포함) 적은 내용이 그대로 남아 있는지, 아무것도 안 쓰고 나가면 초안이 남지 않는지. 제목을 비워 둔 채 제출하면 이슈 제목이 내용 첫 줄(앞의 `#`·`-` 제거, 120자)로 올라가는지, 목록에도 첫 줄이 제목처럼 보이는지. `AI로 정리`는 내용이나 이미지가 있어야 켜지고(⌘/Ctrl+Enter 동일), 누르면 "AI 작성 중…" 뒤 제목·본문(문제/기대 동작/개선 제안)으로 채워지며, 결과를 고친 뒤 그대로 제출할 수 있는지. 하단 모델·Effort 선택은 채팅 하단처럼 테두리 없는 색상 드롭다운(모델은 Haiku/Sonnet/Opus 고유 색, Effort는 낮음=초록 막대 1칸·보통=파랑 막대 2칸)이고 각 항목에 짧은 설명이 보이는지, 'Claude Code 설정' 항목이 없는지, 처음 상태가 Haiku 5.5 + 낮음이고 AI 정리가 `--model claude-haiku-5-5 --effort low`로 실행되는지, Effort에 높음이 없는지(설정에 높음·Claude Code 설정이 저장돼 있어도 하단에는 기본값으로 보이고 그 값으로 실행). 하단에서 바꾼 값이 설정 > 피드백에도 반영되는지.
- 피드백 요청: 설정·용어 정리 (2026-11-12): 화면 어디에도 '피드백 창고'·'AI 초안 모델'·'익명 제출'이 없고 '피드백 요청'·'AI 정리'·'로그인 없이 제출'로 보이는지(헤더 버튼 툴팁, 명령 팔레트, 단축키 설정, 상태바 배지, 플러그인 승인 창). 설정 > 피드백 > **제출 방식**이 둥근 알약 모양인지(계정=초록+사람 아이콘, 로그인 없음=파랑+정보 아이콘 + 아래 작은 글씨 '이 기기에서 5분에 1건씩…', 불가=주황+경고). **AI 정리 모델·Effort**가 하단과 같은 색 드롭다운이고 모델은 Haiku/Sonnet/Opus 5.5뿐, Effort는 낮음·보통뿐인지('높음'·'Claude Code 설정' 없음). 예전에 `높음`·`Claude Code 설정`·`sonnet`·`opus` 별칭을 저장해 둔 사용자는 설정과 하단 모두 기본값(Haiku 5.5·낮음, 별칭은 해당 5.5)으로 보이고 그 값으로 실행되는지. 서버에 `effort: 'high'`를 직접 보내도 `--effort low`로 실행되는지.
- 피드백 요청: AI 정리 진행 표시·속도 (2026-11-12): `AI로 정리`를 누르면 즉시 상단에 스피너·"AI가 정리하는 중… n초"·"보통 10~30초" 안내와 움직이는 진행선이 보이는지(내용 칸은 읽기 전용, 버튼은 "AI 작성 중…"). 다른 화면(목록)으로 갔다가 돌아와도 경과 시간이 이어지고 끝나면 결과가 채워지는지. 45초가 넘으면 안내 문구가 "평소보다 오래 걸리고 있습니다…"로 바뀌고, 2분이 지나면 "AI 정리 시간이 초과되었습니다"로 멈추는지. 속도: 같은 입력을 이전 빌드와 비교해 눈에 띄게 빨라졌는지(원인은 `claude -p`가 사용자의 MCP 서버·스킬·프로젝트 설정까지 모두 띄우던 것이라 `--strict-mcp-config --setting-sources user --disable-slash-commands --no-session-persistence`를 추가함. 이 PC에서 한 줄 답이 기존 10~21초 → 약 5~6초. `--bare`는 OAuth 로그인을 읽지 못해 쓰지 않음). 로그인·프록시·환경 변수를 `~/.claude/settings.json`에 둔 환경(Bedrock 등)에서도 AI 정리가 인증 오류 없이 되는지.

## Chat에서 Artifact 도구 필요할 때만 켜기 (2026-11-12)

배경: `claude -p`(Chat 모드)는 Artifact 도구 3개(`Artifact`, `ArtifactComments`, `ArtifactData`)를 기본으로 끄고, 켜면 요청마다 입력이 약 12.9k 토큰 늘어난다. 그래서 기본은 꺼 두고, 메시지에 `artifact`/`아티팩트`가 들어가면 그 채팅에서만 켠다. 세션 중간에 켜는 건 `apply_flag_settings`(`settings.env.CLAUDE_CODE_ARTIFACT=1`)로 하며, 한 번 켜면 그 프로세스가 끝날 때까지 끌 수 없다(CLI 제약). 채팅 상태(`meta.json`의 `artifact`)에 남겨 재시작·resume에도 유지한다.

테스트는 격리 환경(`ADE_DATA_DIR` 별도 지정)에서 모델 `claude-haiku-5-5`, effort `low`로 한다.

1. 새 채팅에서 "1+1은?"을 보낸다. 입력창 위 토큰이 기준값(약 25k 안팎)인지 본다.
2. 같은 채팅에서 "방금 답을 Artifact로 만들어줘"를 보낸다.
   - 이 턴부터 입력 토큰이 약 1.3만 늘어난다. 모델이 Artifact 도구를 호출하거나 사용하려 한다.
   - 에러 배너가 뜨지 않고 응답이 정상으로 끝난다.
3. 앱을 재시작하고 같은 채팅을 이어서 일반 질문을 보낸다. 토큰이 다시 내려가지 않고(Artifact 유지) 대화가 이어진다.
4. 새 채팅을 열어 일반 질문만 보낸다. 토큰이 기준값으로 시작한다(다른 채팅의 켜짐이 새어 들어오지 않는다).
5. 설정 > "Artifact 항상 켜기"를 켠다.
   - 새 채팅 첫 메시지부터 토큰이 약 1.3만 높게 시작한다.
   - 이미 열려 있던 채팅은 다음 메시지부터 켜진다.
6. 켜기 요청이 거절되는 경우(드문 경우): 거절돼도 에러 없이 메시지는 정상 전송되고, 다음 메시지에서 다시 시도한다.
7. Codex/Cursor 채팅에는 영향이 없다(메시지에 artifact가 있어도 평소처럼 동작).

자동 확인: `node --test tests/chat-claude.test.mjs`의 `wantsArtifact` 케이스.
