# 테스트 실행 안내

현재 결과는 [VERIFICATION](VERIFICATION.md)에서 확인하세요. 모든 명령은 저장소 루트에서 실행합니다.

## 설치와 자동 검사

```sh
pnpm install --frozen-lockfile
pnpm check   # 웹 타입 검사 + Node 테스트
pnpm audit
```

`check`는 `pnpm typecheck`(웹 UI 타입 검사)와 `tests/*.test.mjs`를 실행합니다. 테스트는 임시 저장소·데이터 폴더·가짜 Codex app server를 사용하며 모델을 호출하지 않습니다. 로컬 서버 테스트에는 실제 Git·PTY 호출이 포함됩니다. 제거한 API(`files/*`, `git/commit`, SDK 실행 등)가 404를 반환하는지도 확인합니다.

파일 감시 오류를 집중 확인하려면 `node --test tests/project-watch.test.mjs`를 실행합니다. 생성 실패, 비동기 EMFILE, 경로 배치 상한, 정상 종료 후 지연 이벤트 차단을 검증합니다.

## UI E2E

```sh
pnpm e2e
# Chrome을 찾지 못하면:
CHROME_PATH=/path/to/chrome pnpm e2e
```

`e2e`는 웹 UI를 빌드한 뒤 로컬 서버와 격리된 headless Chrome으로 앱 창과 같은 화면을 띄웁니다. 임시 홈·프로젝트·앱 데이터·Chrome 프로필을 만들고 종료 시 정리합니다. 모델 호출 없이 접속 인증, 토큰 URL 제거, 프로젝트 열기, 실제 PTY 입력과 파일 쓰기, 스크롤백 복원, 에이전트 상태 보고, Git Diff 렌더링, 탭 추가·새로고침 복원을 확인합니다. 같은 Chrome에서 사이드바 네이티브 드래그 테스트도 실행합니다. 페이지 예외·console.error가 있으면 실패합니다. Electron 셸(창·메뉴·폴더 선택)은 이 검사의 범위가 아닙니다.

`pnpm check`에서 사이드바 드래그 테스트가 건너뛰어지는 것은 `ADE_TEST_CDP`가 없기 때문입니다. `pnpm e2e`가 Chrome을 시작하고 해당 테스트에 주소를 전달합니다.

## 화면 전환 애니메이션 · 터미널 방향키

타입체크만 확인했고, 아래는 실행해 보지 않았습니다.

1. 프로젝트 전환, 터미널 탭 전환, 설정 열기·섹션 이동, 명령 팔레트, Diff 패널 열기 시 배경색이 번쩍이지 않고 부드럽게 나타나는지 본다. pane 분할·닫기 때 기존 터미널이 다시 깜빡이지 않아야 한다.
   - 탭을 빠르게 왔다 갔다 해도 터미널 글자가 한 프레임 비거나 다시 그려지지 않는지(숨긴 탭도 WebGL 렌더러를 유지함). 탭 7개 이상에 각각 터미널을 띄우고 돌아다녀도 글자가 깨지거나 WebGL이 꺼지지 않는지(보이는 pane이 슬롯을 필요로 하면 숨은 pane의 슬롯을 회수함). OS의 "동작 줄이기"를 켜면 애니메이션이 없어야 한다.
2. 설정 창을 끌어 옮긴 뒤 닫았다 열어도 위치가 유지되는지 본다(팝 애니메이션이 `scale`만 써서 드래그 오프셋과 겹치지 않아야 함).
3. Claude Code 입력창에 여러 단어를 입력한 뒤:
   - `Alt+←/→` → 단어 단위 이동 (pane이 바뀌면 안 됨)
   - `Cmd+←/→` (macOS) → 줄 처음/끝으로 이동
   - `Ctrl+←/→` (Windows/Linux) → 단어 단위 이동
4. `Alt+Shift+방향키`, `Cmd(Ctrl)+Shift+방향키` → pane 포커스 이동.

## 사용량 조회의 .envrc 적용

1. `.envrc`에 `export CLAUDE_CONFIG_DIR="$HOME/.claude-work"`가 있는 프로젝트에서 `direnv deny`(또는 아직 `direnv allow` 전) 상태로 열고 터미널에 에이전트를 띄우지 않는다 → 상태바 Claude 사용량 팝오버의 계정이 `~/.claude-work (프로젝트 .envrc 기준)`이고, 그 계정의 요금제·사용률이 보인다. `direnv allow` 후에도 같다.
2. `.envrc`가 `export X=$(명령)`처럼 계산이 필요한 값이면 파일을 실행하지 않으므로 기본 계정으로 조회한다(`direnv allow` 후에는 적용된다).
3. 터미널에 `~/.claude`로 실행 중인 에이전트가 있어도 `.envrc`가 계정을 정하면 그 계정으로 조회한다. `.envrc`가 없거나 계정을 정하지 않으면 실행 중인 에이전트의 계정을 따른다.
4. `node --test tests/usage.test.mjs`.

7-1. 입력창의 `Effort` 드롭다운(또는 `/effort`)은 고르기 전에는 `Effort`라고만 표시되고(`--effort` 인자 없음, CLI 설정을 따름) 목록에는 low~max만 있다. 하나를 고르면 저장되고, 실행 중인 claude는 다음 응답 때 `--effort <값>`으로 다시 시작되어 같은 세션을 이어간다(`ps`로 인자 확인). 응답 중에 바꾸면 그 응답이 끝난 뒤 적용된다.
7-2. 새 채팅(대화 전)은 Claude Code Desktop처럼 가운데에 "{사용자}님, 다음엔 무엇을 해 볼까요?" 인사, 칩 행(로컬 · 프로젝트 폴더 · 브랜치+`워크트리` 체크 · 폴더 추가), 한 줄 입력창, 하단 줄(`+` 첨부 · 권한 모드 · 모델 · Effort · 컨텍스트 링)이 보인다. 첫 메시지를 보내면 칩 행과 인사가 사라지고 입력창이 아래로 내려간다.
7-2-1. 하단 줄 오른쪽 원형 링은 컨텍스트 사용률이며, 클릭하면 위로 팝오버가 열려 컨텍스트 사용량과 Claude 사용 한도(5시간·주간, 초기화 시각, 플랜)가 보인다. 값은 하단 상태바의 Claude 사용량과 같은 조회이고 열 때 새로고침된다. 바깥 클릭·Esc로 닫힌다. 채팅 상태 줄(진행 상태·토큰·비용)은 입력창 바로 위에 입력창 폭으로 붙고(빈 새 채팅에서는 숨김), 모델·모드·Effort·링과 보내기 버튼(둥근 아이콘)이 있는 하단 줄은 입력창 카드 안쪽 아래에 들어 있고, 카드 아래에는 여백이 있다. 상태 줄 위에서 대화 내용은 아래쪽으로 살짝 흐려지며 사라져 글자가 줄에 붙어 보이지 않는다. 대화를 위로 240px 넘게 올리면 입력창 위 가운데에 '맨 아래로' 둥근 버튼이 나타나고, 누르면 부드럽게 맨 아래로 내려가며 이후 새 응답을 따라간다.  기본 항목은 진행 상태·토큰·비용이다(모델·모드·컨텍스트는 하단 줄에 있어 중복되지 않음). 예전 기본 설정을 그대로 쓰던 경우만 새 기본으로 바뀌고, 직접 바꾼 설정은 유지된다.
7-3. `워크트리`를 체크하고 첫 메시지를 보내면 `<프로젝트>/.claude/worktrees/<이름>`이 만들어지고(`git worktree list`) claude가 그 안에서 실행된다. 대화가 시작된 뒤에는 체크박스가 잠긴다. 확인 후 `git worktree unlock <경로>` → `git worktree remove <경로>`로 정리한다.
7-4. 폴더 추가 버튼은 OS 폴더 선택창으로만 경로를 고른다(직접 입력 없음). 고른 폴더는 칩으로 보이고 `x`로 뺄 수 있으며, 실행 중이면 `--add-dir`로 claude가 다시 시작된다(최대 8개). 하단 줄의 인사 이름은 OS 사용자 이름이고 로컬 화면에만 표시된다.
8. 응답이 끝나면 완료 알림·소리가 터미널 에이전트와 같게 동작한다.
9. 스티어링·팔로업: 응답 중 입력창에서 Enter → 메시지가 점선 테두리의 '스티어링 · 대기 중 · Esc로 취소' 말풍선으로 응답 진행 표시(생각 중/도구 카드) **아래**에 붙는다(위로 올라가지 않는다). CLI가 그 메시지를 받아들이면 일반 사용자 말풍선으로 바뀌고 응답에 반영된다(예: 긴 Bash 실행 중 "답에 STEERED를 덧붙여줘"). 대기 중에 Esc → 말풍선이 사라지고 문구가 입력창에 돌아오며(입력창이 비어 있을 때만) 응답은 중단 없이 계속되고 그 메시지는 처리되지 않는다. 대기 중인 스티어링이 없을 때의 Esc는 기존처럼 응답을 중단한다. Tab → 응답이 끝난 뒤 보내는 팔로업 대기열(설정의 follow-up 큐가 켜진 경우).
10. 생각 중 표시: 응답을 기다리는 동안 스피너(느리게 회전) · 경과 시간 · 추정 토큰 · Effort 이름이 보이고 오래 걸릴수록 Effort 글자가 빨개진다. CLI가 생각 내용 자체는 주지 않으므로 '무슨 생각을 하는지' 글은 나오지 않는다(토큰 추정치만). 도구가 실행 중이면 이 줄은 숨는다. 응답 글은 한 번에 튀어나오지 않고 부드럽게 이어서 나타난다(모션 줄이기 설정 시 즉시 표시).
11. 복사·Branch·Rewind: 응답이 끝난 턴의 마지막 어시스턴트 메시지 왼쪽 아래에 복사 · Branch · Rewind 아이콘이 항상 보인다. Branch → 그 지점까지의 대화를 가진 새 채팅 탭이 열리고(`--resume <id> --resume-session-at <uuid> --fork-session`) 이어서 물으면 그 지점까지의 맥락으로만 답한다. Rewind → 확인 후 그 메시지 아래 대화가 사라지고 '여기까지 되돌렸습니다' 안내가 나오며 다음 메시지는 그 지점부터 이어진다(되돌린 뒤 이전 내용을 물으면 모른다고 답함). 대화 기록만 되돌리며 Claude가 이미 바꾼 파일은 그대로다.
12. 권한 모드: 하단 줄의 모드 앞에 아이콘이 있다(기본 방패 · 편집 허용 편집 노트 · 계획 문서 · 모두 허용 번개). 입력창에서 Shift+Tab → 기본 → 편집 허용 → 계획 → 기본 순으로 바뀐다. `모두 허용`은 순환에 없고 드롭다운으로만 고르며, 그 상태에서 Shift+Tab이면 기본으로 나온다. 응답 중에 바꾸면 응답이 끝난 뒤 적용된다(CLI 재시작, 같은 세션). 슬래시 메뉴가 열려 있어도 Shift+Tab은 모드 전환이다.
13. 하단 줄의 모드·모델·Effort 버튼은 가로 8px·세로 4px 여백이고, 호버하면 배경이 들어온다(닫은 뒤 키보드 포커스 때도 테두리 대신 배경). 모델 이름은 굵게 보이고 계열 색 그대로다. 모드도 각각 색이 있다(기본 회색 · 편집 허용 초록 · 계획 파랑 · 모두 허용 빨강, 라이트 테마에서는 더 진하게). 눌러서 열리는 메뉴는 둥근 카드에 여백·둥근 행으로 나오고, 현재 선택은 옅은 배경과 체크로 표시된다.

2. 새 탭, 분할 창, 새 탭 메뉴, 명령 팔레트에 설치된 Provider가 Claude·Codex·Cursor 이름으로 하나씩 표시되는지 확인한다. 터미널 설명은 선택한 셸 이름이며 자동 선택·삭제된 셸은 서버의 실제 기본 셸 이름으로 표시한다. 카드 안의 아이콘과 이름은 세로 중앙에 정렬한다. 새 탭에는 부제 없이 제목과 모드 선택이 표시되고 배경은 은은한 빛으로 표현한다. 제목과 카드가 차례로 나타나며 모션 줄이기 설정에서는 등장 애니메이션을 생략한다. 꺾쇠 메뉴는 모드 선택 후 Provider를 열고, 일반 터미널은 구분선 아래에서 셸 이름과 함께 표시한다. Escape·바깥 클릭으로 닫고 꺾쇠 버튼으로 포커스가 돌아오는지 확인한다.
3. 이전 버전 설정(defaultMode 필드 없음)으로 업데이트하면 CLI 기본값을 유지한다. 활성 CLI pane에서 Claude·Codex·Cursor를 이용할 때 하단에 이미지가 있는 Chat 안내가 표시된다. 새 설치, Chat pane, 일반 셸에서는 표시되지 않는다.
4. 안내를 닫은 후 다른 프로젝트·Provider·재시작·설정 초기화에서도 다시 표시되지 않는지 확인한다. ‘Chat 모드 사용하기’는 같은 Provider로 새 Chat 탭을 열고 기본 모드를 Chat으로 저장한다. 원래 CLI 대화는 유지된다.


## Effort 효과: 매우 높음 · 최대 (2026-11-10)

구현만 하고 실행해 보지 않았습니다. `pnpm typecheck`(`tsc --noEmit`)는 오류 없이 통과했습니다. 화면에서의 모습은 확인하지 않았습니다.

1. 입력창 하단의 Effort 드롭다운을 `매우 높음`으로 고른다. 드롭다운 안에서 주황 입자 7개 안팎이 천천히 떠올랐다 사라진다. 입자는 2~2.8px 크기에 불투명도 70~95%로 떠오르며, 좌우로 조금 흔들린다. 입자는 글자 뒤에 있어 글자를 가리지 않는다. 발광(빛 번짐)과 배경 덩어리는 없어야 하고, 아이콘은 움직이지 않고, Effort 글자는 굵게(600, 모델 이름과 같은 굵기) 보여야 한다.
2. `최대`로 고른다. 빨강·주황·노랑 입자 20개 안팎이 `매우 높음`보다 빠르게, 드롭다운 박스 안에서만 떠오른다. 그중 약 18%는 크고 빛이 번진다. 왼쪽 불꽃 아이콘은 단색 빨강으로 흔들림 없이 0.7초마다 1배와 1.12배 사이를 오간다. 글자(`최대`)는 빨강·주황 사이 그라데이션이 2.4초 주기로 흐른다.
3. `높음` 이하 단계에서는 입자도 불꽃 움직임도 없어야 한다.
4. macOS 시스템 설정 → 손쉬운 사용 → 디스플레이 → `동작 줄이기`를 켜면 두 단계 모두 입자·불꽃·글자 그라데이션 움직임이 멈춘다. 이 설정이 켜져 있으면 입자는 보이지 않는 것이 의도된 동작이다.
5. 입자가 입력창의 글자 위로 넘어가지 않아야 한다. 입자 위에서도 드롭다운은 그대로 눌리고 열려야 한다(입자는 클릭을 받지 않는다). 입자는 Effort 칸(약 28px 높이) 안에서만 떠오른다. 위쪽 입력창 글자를 가리지 않기 위해서다.

확인하지 않은 것: 두 단계의 실제 체감 강도(은은함·강인함), 라이트 테마에서 최대 글자 그라데이션의 대비, 브라우저별 글자 그라데이션(background-clip) 표시, 좁은 화면.


## Chat 시작 화면과 이전 대화

- 시작 화면의 Provider 아이콘은 32px이며 떠다니지 않는다. 브랜드 색의 고정된 빛과 Provider별 배경이 표시된다. 로컬·작업 경로·추가 경로 칩과 폴더 추가 버튼은 표시하지 않는다.
- 모델 메뉴와 전체 모델 목록에는 ‘기본 모델’ 항목이 없다. CLI가 알려준 실제 모델 이름이 표시되며, 조회되지 않으면 모델을 직접 선택한다.
- 대화가 없는 시작 화면의 입력창 아래 ‘이전 대화 불러오기’와 `/resume`는 같은 목록을 연다. 범위는 현재 프로젝트에서 같은 Provider로 저장된 ADE Chat 기록이다. CLI 자체 기록은 포함하지 않는다.
- 닫은 Chat도 목록에서 불러올 수 있다. 이미 열려 있으면 그 탭으로 이동하고, 닫힌 대화는 새 탭으로 연다. 현재 작성 중인 입력은 유지한다. `/clear` 이전 대화도 보관되며, 목록이 없거나 선택을 취소해도 현재 대화는 유지된다.
