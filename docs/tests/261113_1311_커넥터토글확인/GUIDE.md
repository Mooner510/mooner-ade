# Chat 비개발 도구(claude.ai 커넥터) 실행 중 활성화 가능 여부 확인

목적: 커넥터를 끈 채로 시작한 `claude` 프로세스에 **재기동 없이** 커넥터를 켤 수 있는지(방법 B) 판정한다. 안 되면 `--resume` 재기동(방법 A)으로 간다.

## 실행

1. 저장소 루트에서 실행한다. ADE를 거치지 않고 `claude`만 직접 띄우므로 ADE 데이터에 영향이 없다. claude.ai 로그인이 필요해 HOME은 그대로 둔다:
   ```
   node docs/tests/261113_1311_커넥터토글확인/probe.mjs
   ```
2. 출력의 `== 1.` ~ `== 2d.`를 본다. 이 단계는 **사용량을 소모하지 않는다**(제어 요청만 보냄).
3. 2d에서 커넥터가 보일 때만, 도구 노출 확인으로 한 번 더 실행한다(**haiku·low 한 턴, 사용량 소모**):
   ```
   node docs/tests/261113_1311_커넥터토글확인/probe.mjs --ask
   ```

## 판정

| 관찰 | 결론 |
|---|---|
| 1에서 `claude.ai …` 서버가 없음 | 전제 성립(끈 채로 시작됨). 있으면 `--settings`가 안 먹는 것 → 환경변수 방식으로 재시험 |
| 2b에서 이미 나타남 | `apply_flag_settings`만으로 충분 (B 가능, 가장 단순) |
| 2d에서만 나타남 | `apply_flag_settings` + `reload_plugins` 조합 필요 (B 가능) |
| 2d에도 없음 | `mcp_reconnect`(서버 이름 필요)나 `mcp_set_servers`는 대상이 없을 가능성이 커서 B 불가 → A로 진행 |
| `--ask`에서 도구 이름이 나열됨 | 다음 턴 모델 노출까지 확인됨 → B 확정 |
| `--ask`에서 도구가 없다고 함 | 서버는 붙었지만 프롬프트 반영 실패 → A로 진행 |

## 주의
- 응답 형식(`mcp_status`의 필드)은 확인하지 못했다. 출력은 원문 그대로 1,800자까지 보여주니 서버 이름 목록 위주로 본다.
- 제어 요청에 응답이 없으면 `timeout`으로 나온다. 이때는 첫 사용자 메시지 뒤에야 제어 요청을 받는 구조일 수 있으니 알려 달라.
- `--ask`는 도구를 호출하지 않게 했다. 계정 데이터는 읽지 않는다.
- 결과를 알려주면 이어서 A/B 중 하나로 설정 토글을 구현한다.
