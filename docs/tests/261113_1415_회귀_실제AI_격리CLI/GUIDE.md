#### Chat → 터미널 전환 (반대 방향)

5. 왕복(터미널 → Chat → 터미널)을 해도 대화가 이어지고 중복되지 않는다.

#### 알려진 한계
- 지원 범위: `/resume`은 지원하지 않습니다(터미널 탭 사용). `/rewind` 명령 대신 메시지 아래 Rewind 아이콘을 씁니다. Branch·Rewind는 턴의 마지막 메시지에만 나오고, 이 기능 이전에 저장된 메시지(uuid 없음)에는 없습니다. `AskUserQuestion`은 질문 카드로 보이고, 답은 도구 입력으로 돌려줍니다. 입력창의 마이크(음성 입력)는 없습니다. Windows `claude.cmd` 실행, 코드 구문 강조, Codex 채팅(2단계)도 아직 없습니다.
- 수치: 컨텍스트 창 크기는 첫 응답 전에는 추정(200k, 모델명에 `[1m]`이면 1M)이고 이후에는 CLI가 보고한 값입니다. 링 팝오버의 사용 한도는 상태바와 같은 조회라 5시간·주간 한도만 보이며, 사용 크레딧(금액) 막대는 없습니다.
- 화면에 없는 것: 워크트리 켜기와 폴더 추가 컨트롤은 PR #42에서 제거됐습니다(서버 옵션만 남음, 최대 8개). 예전에 만들어진 워크트리는 직접 정리해야 합니다(`git worktree unlock` → `remove`).
- 재시작이 필요한 설정: Effort와 접근 폴더를 바꾸면 실행 중인 claude가 다시 시작됩니다(같은 세션을 이어가며, 응답 중이면 끝난 뒤 적용). Effort를 고르기 전에는 `--effort` 없이 CLI 설정을 따르며, 한 번 고른 뒤에는 기본으로 되돌리는 항목이 없습니다.
- 설정 이전: 채팅 상태 줄의 새 기본 항목(사용량 기여도)은 예전 기본 설정(토큰·비용)을 그대로 쓰던 경우에만 자동 추가됩니다. 직접 바꾼 설정은 유지되어 하단 줄과 중복될 수 있습니다(설정 → 기본값으로).
- 스티어링: 응답이 이미 끝나갈 때 보낸 메시지는 CLI가 다음 턴으로 처리할 수 있고, 취소는 CLI가 아직 받아들이기 전일 때만 성공합니다(이미 받아들였으면 취소되지 않고 일반 말풍선이 됩니다).
- 아직 직접 확인하지 못한 것: 라이트 테마·좁은 화면의 새 레이아웃과 링 팝오버 위치, 슬래시 메뉴 위치, `/effort`, 대화가 쌓인 기존 탭의 입력창 배치, 상태바 사용량 팝오버(공용 코드로 분리한 뒤) 재확인, Electron 앱·패키징 앱에서의 동작(테스트는 서버 단독 + Chrome으로만 진행).

원인: 채팅이 `--mcp-config`(에이전트 버스)로 Claude Code를 띄우면, CLI가 사용자의 다른 MCP 서버(느리거나 응답 없는 서버)가 모두 연결될 때까지 `init`을 잡고 있었다(claude 2.1.322 실측: 플래그 없음 1.1초, 있음 29.7초). ADE가 `CLAUDE_CODE_MCP_STARTUP_WAIT_MS=3000`을 넘겨 이 대기를 3초로 제한한다. Codex(시작 0.2~0.5초)와 Cursor(약 6초, 포커스 시 미리 시작)는 해당 없음.

1. 새 Claude Chat을 열고 `안녕`을 보낸다. 응답이 시작되기까지 약 3~5초 이내여야 한다(수정 전 약 30초).
2. 에이전트 버스가 켜진 채팅에서 "list_peers 도구를 호출해줘"를 보낸다. 첫 턴에서도 도구가 호출돼야 한다.
3. `CLAUDE_CODE_MCP_STARTUP_WAIT_MS=9000`으로 ADE를 실행하면 그 값을 따른다(이 변수를 직접 지정한 경우 덮어쓰지 않음).
4. `node --test tests/chat-session.test.mjs` — "MCP startup wait" 테스트.

### 입력창 위 토큰(↑입력 ↓출력)이 올랐다 0으로 돌아가던 문제 (2026-11-12)

원인: 한 턴이 여러 API 호출(도구 루프)일 때, 새 호출이 시작될 때마다 진행 중 합계(`turnUsage`)를 비워서 표시값이 기준(`state.tokens`)으로 되돌아갔다. 끝난 호출을 `turnDone`에 모아 두고 result에서 한 번에 확정하도록 고쳤다. 아직 직접 실행해 확인하지 않았다.

- 자동: `node --test tests/chat-session.test.mjs` (새 케이스: 호출 2번짜리 턴에서 표시값이 줄지 않고 result 합계로 끝남)
- 수동: 파일 읽기·편집처럼 도구를 여러 번 쓰는 요청을 보내고, 턴 동안 ↑↓ 값이 계속 늘기만 하는지 확인한다. 턴이 끝난 뒤 값이 크게 달라지지 않아야 한다.
- 참고: ↑입력은 캐시 읽기·쓰기를 뺀 순수 입력이라 "세션 총 입력"보다 작다. 캐시는 `{cache}`, 합계는 `{total}` 자리표시자로 따로 쓴다.

### 수동 수용 검사 중 실제 Claude가 필요한 항목 (옛 31줄 섹션)

- 실제 Claude/Codex CLI의 질문·승인·완료, SSH/tmux, follow-up 대기·취소·재연결 확인
- 캐시 타이머(`node --test tests/claude-cache.test.mjs`로 transcript 해석부터 확인): 로컬 Claude Code에서 한 번 요청하면 3초 안에 그 Claude pane 헤더 왼쪽에 🔥 `59:5x`(TTL은 transcript의 `promptCacheRequested` 값, 현재 구독 계정은 1시간)가 뜨는지, 남은 시간이 20% 아래로 내려가면 아이콘 없이 노란 시간만, 만료되면 글자 없이 파란 ❄️ 눈꽃 아이콘만 남는지(툴팁에는 식었다는 설명이 그대로), Claude가 작업 중일 때는 시간 대신 🔥 `캐시 사용중`이 뜨고 작업이 끝나면 다시 시간으로 돌아오는지, 툴팁의 마지막 요청 시각이 실제 요청 시작과 맞는지 확인. 자동 compact(idle compaction)가 켜진 환경(기본값, `autoCompactEnabled`·`idleCompaction`이 꺼져 있지 않고 `DISABLE_AUTO_COMPACT` 없음)에서 컨텍스트가 20만 토큰 이상인 1시간 캐시 대화는 카운트다운이 59분이 아니라 약 54분(`IDLE_LEAD` 0.9)에서 끝나고 툴팁이 "자동 compact" 문구로 바뀌는지, 실제로 Claude 터미널에 `Compacted while idle, before the prompt cache expired` 안내가 뜨는 시각과 맞는지(다르면 `claude-cache.js`의 `IDLE_LEAD` 조정), `/config`나 settings에서 끄면 다음 요청부터 다시 약 60분으로 돌아가는지 확인. 20만 토큰 미만이거나 5분 TTL이면 기존과 같아야 합니다. compact가 끝나면(수동 `/compact`, 컨텍스트가 차서 일어나는 자동 compact, idle compaction 모두) 3초 안에 타이머가 보라색 보관함 아이콘으로 바뀌고 툴팁에 compact 시각·수동/자동·토큰 변화(`223K → 19K`)가 뜨는지, 그 뒤 다음 메시지를 보내면 새 카운트다운으로 돌아오는지 확인. idle compaction이 실제로 일어났을 때 툴팁이 '자동'으로 나오는지도 확인(transcript의 `compactMetadata.trigger` 값이 `auto`가 아니면 알려주세요). Claude pane을 여러 개 띄우면 각 pane 헤더에 자기 대화 기준 타이머가 따로 뜨고, `/clear` 직후·Claude 종료·SSH 안의 Claude에서는 타이머가 사라져야 합니다. 사이드바에서는 지금 보고 있지 않은 탭(분할 탭은 각 pane 줄)의 오른쪽 끝에만 같은 타이머가 작게 뜨고, 그 탭을 선택하면 사이드바에서 사라지는지, 알림 점·닫기 버튼과 겹치지 않는지 확인.
- 캐시 만료 전송 경고(`node --test tests/claude-cache-warning.test.mjs tests/ai-settings.test.mjs`로 판정부터 확인): 설정 > AI 툴 > Claude Code에서 "캐시 만료 시 전송 경고"가 기본 켜짐이고 기준 시간 10분인지. 1시간 캐시의 Claude pane에서 캐시가 식었거나 남은 시간이 기준 이하일 때 메시지를 쓰고 Enter를 누르면 보내기 전에 "프롬프트 캐시가 … 보낼까요?" 선택창이 뜨고, 첫 항목 "취소"가 선택된 상태인지(Enter 한 번 더로 보내지지 않음). 취소·Esc 후에는 메시지가 전송되지 않고 입력한 글이 그대로 남아 있는지, "그래도 보내기"를 고르면 그대로 전송되는지. 한글 IME 조합 중 Enter, 선택창이 떠 있는 동안 키 입력, 선택창을 닫은 뒤 터미널 포커스. 슬래시 명령(`/clear`)·`@` 자동완성 선택·빈 입력·권한 대화상자·작업 중(Esc 전 Enter)에는 뜨지 않는지, 5분 캐시 계정은 완전히 식었을 때만 뜨는지. Tab으로 후속 대기열에 쌓은 메시지가 캐시가 식은 뒤 자동 전송될 때도 같은 선택창이 뜨고, 거절하면 보내지 않은 채 대기열에 남으며 같은 캐시에서 반복해서 묻지 않는지. 설정에서 끄거나 분을 바꾸면 바로 반영되는지(재시작 불필요).
