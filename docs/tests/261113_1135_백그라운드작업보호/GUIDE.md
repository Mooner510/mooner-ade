# 백그라운드 작업 보호 — 수동 테스트 가이드

대상: 백그라운드 서브에이전트(`liveTasks`)가 도는 Claude 채팅이 확인 없이 종료되지 않는지.
준비: 별도 `ADE_DATA_DIR`로 ADE를 띄우고, Claude 채팅에서 "서브에이전트를 백그라운드(run_in_background)로 오래 걸리는 작업에 실행하고 바로 답해"라고 요청한다. 응답이 끝나 idle인데 `/tasks`에 '실행 중'이 보이는 상태가 시작점이다.

| # | 동작 | 기대 결과 |
|---|---|---|
| 1 | `/clear` 입력 | "백그라운드 작업이 실행 중입니다…" 선택창. 취소하면 아무 일 없음, 시작하면 새 대화 |
| 2 | 헤더 `+`(새 대화) 클릭 | 1번과 같음 |
| 3 | 헤더 터미널 전환 버튼 | 확인창. 취소하면 채팅 유지, 확인하면 같은 세션이 터미널로 열림 |
| 4 | `/exit`, 헤더 X, `Alt+W` | 설정 "채팅 닫기 확인"이 꺼져 있어도 확인창이 뜸 |
| 5 | 탭 X, 탭 가운데 클릭, `Ctrl/Cmd+Shift+W` | 확인창에 "백그라운드 작업이 있는 채팅 N개" 표시 |
| 6 | 프로젝트 닫기 | 확인창. 터미널이 없으면 확인창은 한 번만 뜸 |
| 7 | 앱 종료(Cmd+Q) | "진행 중인 채팅 응답이 N개" 확인창 |
| 8 | 작업 중 모델 기본값/effort 변경 | 즉시 재시작하지 않음. 작업이 끝난 뒤 적용 |
| 9 | 백그라운드 작업 중 10분 방치 | child가 종료되지 않음. 작업이 모두 끝나면 10분 뒤 종료 |
| 10 | 백그라운드 작업 없음 | 위 모든 동작이 기존과 같음(확인 없이 동작, 10분 뒤 유휴 종료) |

서버 직접 확인: 작업이 도는 채팅에 `chat/reset`, `chat/to-terminal`을 `force` 없이 호출하면 409 `CHAT_BACKGROUND`, `force: true`면 진행.

알려진 한계: shell, Monitor, ScheduleWakeup은 `liveTasks`에 잡히지 않아 이번 변경으로 보호되지 않는다(세션 상태 파일 연동은 후속).
