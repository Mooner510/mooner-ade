## 목적과 의도한 결과
구현만 하고 화면 확인을 하지 못한 UI·설정 변경이 지금 브랜치에서 의도대로 보이고 동작하는지 한 번에 확인한다. 각 섹션의 "기대"가 성공 기준이다.

## 사전조건
- 모드 A 세션(`node scripts/verify/start-ui.mjs`). 실제 AI는 필요 없다.
- 기초 검사(`pnpm typecheck`, `node --test`)는 처음과 끝에서만. 일부 항목이 가리키는 단위 테스트는 끝의 `node --test`에 포함된다.
- 사이드바 드래그 항목은 `pnpm e2e`가 master에서도 첫 단언에서 실패하는 문제(원인 미조사)와 연결된다.

### 화면 전환 애니메이션 · 터미널 방향키

타입체크만 확인했고, 아래는 실행해 보지 않았습니다.

1. 프로젝트 전환, 터미널 탭 전환, 설정 열기·섹션 이동, 명령 팔레트, Diff 패널 열기 시 배경색이 번쩍이지 않고 부드럽게 나타나는지 본다. pane 분할·닫기 때 기존 터미널이 다시 깜빡이지 않아야 한다.
   - 탭을 빠르게 왔다 갔다 해도 터미널 글자가 한 프레임 비거나 다시 그려지지 않는지(숨긴 탭도 WebGL 렌더러를 유지함). 탭 7개 이상에 각각 터미널을 띄우고 돌아다녀도 글자가 깨지거나 WebGL이 꺼지지 않는지(보이는 pane이 슬롯을 필요로 하면 숨은 pane의 슬롯을 회수함). OS의 "동작 줄이기"를 켜면 애니메이션이 없어야 한다.
2. 설정 창을 끌어 옮긴 뒤 닫았다 열어도 위치가 유지되는지 본다(팝 애니메이션이 `scale`만 써서 드래그 오프셋과 겹치지 않아야 함).
3. Claude Code 입력창에 여러 단어를 입력한 뒤:
   - `Alt+←/→` → 단어 단위 이동 (pane이 바뀌면 안 됨)
   - `Cmd+←/→` (macOS) → 줄 처음/끝으로 이동
   - `Ctrl+←/→` (Windows/Linux) → 단어 단위 이동
4. `Alt+Shift+방향키`, `Cmd(Ctrl)+Shift+방향키` → pane 포커스 이동.

### 사이드바 탭 조작 개편 (2026-11-09)

타입체크와 단위 테스트만 확인했고, 사이드바 드래그 e2e(`pnpm e2e`, `tests/sidebar-drag.test.mjs`)와 아래 항목은 실행하지 않았습니다.

1. 분할 탭: 머리줄(레이어 아이콘 + 이름 + 개수)을 끌면 탭 전체가, 그 아래 터미널 줄을 끌면 그 터미널만 움직이는지. Shift 없이 동작해야 한다.
   - 터미널을 끄는 동안 목록 아래에 "여기에 놓으면 새 탭으로 분리" 칸이 뜨고, 놓으면 새 탭이 되는지. 탭 사이(위/아래 가장자리)에 놓으면 그 위치에 새 탭으로 분리되는지.
   - 다른 탭 가운데에 놓으면 "이 탭으로 옮기기"(터미널) / "분할로 합치기"(탭) 배지가 보이고 놓으면 그대로 되는지. 같은 그룹 안에 놓으면 아무 변화 없음.
2. 우클릭 메뉴(탭·분할 머리줄·터미널 줄): 이름 바꾸기, 위/아래로 이동, 위/아래 탭과 분할로 합치기, 탭 닫기, 터미널 줄은 추가로 새 탭으로 분리·위/아래 탭으로 옮기기·이 터미널 닫기. 맨 위/아래 탭에서는 해당 항목이 비활성. Esc·바깥 클릭으로 닫히고 ↑/↓로 항목 이동, 화면 아래 끝에서 열어도 잘리지 않는지.
3. 사이드바 줄에 포커스(Tab 키)한 상태에서 `F2` 이름 바꾸기, `Delete` 닫기, `Alt+↑/↓` 순서 이동, `Shift+F10` 메뉴.
4. 어디서든 `Alt+Shift+[` / `Alt+Shift+]` → 현재 탭 위/아래로 이동. 명령 팔레트의 "포커스된 pane을 새 탭으로 분리".
5. 보기: 분할 탭이 가벼운 박스로 바뀌었는지, 트리 세로선이 폴더 펼침 화살표 중심과(분할 안 세로선은 레이어 아이콘 중심과) 맞는지, 하단 "N개 프로젝트" 문구가 사라졌는지. 다크·라이트 모두.

### 설정 커스터마이징 확장 · 고급 옵션 접기 (2026-11-09)

검증 상태: `pnpm typecheck` 통과만 확인했습니다. 아래 화면 동작은 실행해 보지 않았습니다.

| 외관 > 전체(고급) | 사이드바 너비 | 값 변경 시 너비가 바뀌고, 경계 드래그와 값이 서로 반영된다 |

| 터미널(고급) | 스크롤백·스크롤 속도 | 값 변경 시 열려 있는 터미널에 즉시 반영되고 크기가 어긋나지 않는다 |

| 외관 > 상태 표시 | 12시간제·초 표시 | 상태바 시계가 오전/오후, 초 단위로 바뀌고 초를 끄면 1초 갱신이 멈춘다 |

### 팁(Tip) 표시: 컨텍스트가 길 때 /clear 안내 등 (2026-11-09)

검증 상태: `pnpm typecheck` 통과만 확인했습니다. `tests/tips.test.mjs`는 작성만 했고 실행하지 않았습니다(`node --test tests/tips.test.mjs`). 화면 동작은 확인하지 않았습니다.

동작: 팁은 해당 터미널 pane의 **헤더(제목 자리)** 에 한 줄로 10초간 표시되고 자동으로 사라집니다. 터미널 출력 위에 겹치지 않고 터미널 크기도 바뀌지 않습니다. 클릭하면 바로 닫히고, 줄임표(…)로 잘렸으면 마우스를 올려 전체 문장을 봅니다. 질문·승인 대기(⚠) 중에는 그 자리를 쓰지 않아 팁이 뜨지 않습니다. 설정 → AI → Claude의 ‘팁 표시’로 끄고, ‘컨텍스트 팁 기준(k 토큰)’(기본 400, 1M 컨텍스트의 40%)을 바꿉니다. 기록은 localStorage `ade:tips`에 있고, 지우면 팁이 다시 나옵니다.

### 기본 모드와 Chat 업데이트 안내

1. 새 프로필의 첫 온보딩에서 Chat 모드·CLI 모드를 선택한다. 새 탭 화면과 상단 새 탭 꺾쇠 메뉴의 Chat·CLI 선택 버튼에서도 바꿀 수 있다. 설정 > 외관의 ‘새 탭 기본 모드’에서도 바꿀 수 있다. 이미 열린 세션은 그대로이고 다음 실행부터 선택한 모드가 적용된다.
2. 새 탭, 분할 창, 새 탭 메뉴, 명령 팔레트에 설치된 Provider가 Claude·Codex·Cursor 이름으로 하나씩 표시되는지 확인한다. 터미널 설명은 선택한 셸 이름이며 자동 선택·삭제된 셸은 서버의 실제 기본 셸 이름으로 표시한다. 카드 안의 아이콘과 이름은 세로 중앙에 정렬한다. 새 탭에는 부제 없이 제목과 모드 선택이 표시되고 배경은 은은한 빛으로 표현한다. 제목과 카드가 차례로 나타나며 모션 줄이기 설정에서는 등장 애니메이션을 생략한다. 꺾쇠 메뉴는 모드 선택 후 Provider를 열고, 일반 터미널은 구분선 아래에서 셸 이름과 함께 표시한다. Escape·바깥 클릭으로 닫고 꺾쇠 버튼으로 포커스가 돌아오는지 확인한다.
3. 이전 버전 설정(defaultMode 필드 없음)으로 업데이트하면 CLI 기본값을 유지한다. 활성 CLI pane에서 Claude·Codex·Cursor를 이용할 때 하단에 이미지가 있는 Chat 안내가 표시된다. 새 설치, Chat pane, 일반 셸에서는 표시되지 않는다.
4. 안내를 닫은 후 다른 프로젝트·Provider·재시작·설정 초기화에서도 다시 표시되지 않는지 확인한다. ‘Chat 모드 사용하기’는 같은 Provider로 새 Chat 탭을 열고 기본 모드를 Chat으로 저장한다. 원래 CLI 대화는 유지된다.
