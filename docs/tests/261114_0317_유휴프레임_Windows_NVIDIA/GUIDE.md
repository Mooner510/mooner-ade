# 유휴 프레임 감소 — Windows + NVIDIA 실기 확인

- 일시: 2026-11-14 03:17 (KST) · 브랜치: `perf/optimize` (기준 `f9b1181`)
- 이 GUIDE는 이번 세션에서 확인하지 못한 항목만 담습니다. 모두 확인되면 이 폴더를 삭제합니다.

## 목적
화면이 가만히 있거나 창이 뒤에 있을 때(다른 앱·게임이 앞에 있을 때)는 창이 프레임을 그리지 않아야 한다. 에이전트가 일하는 동안 앞에 있는 창에서는 단순 애니메이션이 원래대로 부드럽게 움직여야 한다. 그래야 RTX HDR(nvppex.dll)이 붙어 있어도 쉬는 동안 GPU 프로세스가 Present 대기로 코어를 잡지 않는다. macOS Chrome(120Hz)에서는 이번 세션에 측정해 확인했다. Windows + NVIDIA 실기에서는 확인하지 못했다.

## 미확인 항목
| 항목 | 못 한 이유·필요한 것 | 확인 절차 | 기대 |
|---|---|---|---|
| 유휴 시 GPU·CPU | Windows + NVIDIA GPU, NVIDIA App에서 RTX HDR 켬, 드라이버 프로필 **없음**(ADE의 "해결"을 누르지 않은 상태) | 1. 패키지 앱을 실행한다.<br>2. 채팅 탭을 열고 Effort를 "최대"로 둔 채 마우스를 치운다.<br>3. 작업 관리자 › 세부 정보에서 `MoonerADE.exe --type=gpu-process`의 CPU를, 성능 탭에서 GPU 3D 사용률을 1분 관찰한다. | GPU 프로세스 CPU가 거의 0이고 3D 사용률이 바닥이다. 수정 전에는 코어 절반 수준이었다. |
| 작업 중 GPU·CPU | 위와 같은 환경, Claude 로그인 | 1. 터미널 탭에서 Claude를 실행해 긴 작업을 시킨다(사이드바에 작업 링이 돈다).<br>2. Chat 탭에서도 턴을 하나 실행한다.<br>3. ADE를 앞에 둔 채 1분, 다른 앱을 앞에 둔 채 1분 관찰한다. | 앞에 있을 때는 스피너·정지 버튼·작업 링이 부드럽게 돈다. 뒤에 있을 때는 멈추고 GPU 프로세스 CPU가 거의 0이다. |

## 참고
- 이번 세션 측정(macOS, 120Hz). fps는 CDP trace의 DrawFrame, CPU는 렌더러 + GPU 프로세스(코어 1개 대비 %)다.
  - Effort 최대 + 입력 대기: 120fps → 2.3fps, 2.3%
  - 작업 링(터미널 표시 중, 앞에 있음): CSS 120fps → JS 24fps, 약 18%. 뒤에 있으면 0fps, 0.6%
  - Chat 턴 실행 중(앞에 있음): 120fps, 약 40%. 스피너·숨쉬기를 원래대로 부드럽게 둔 비용이며, 무엇이든 움직이면 매 vsync마다 화면 전체 레이어를 합성하는 고정비가 대부분이다.
  - Chat 턴 실행 중(뒤에 있음): 1.1fps, 2.1%
- RTX HDR 감지·드라이버 프로필 안내(`apps/desktop/src/nvidia-rtx-hdr.js`)는 그대로 둔다. 앞에 있는 창이 부드럽게 그리는 프레임은 여전히 Present마다 약 49ms씩 붙잡히기 때문이다.
