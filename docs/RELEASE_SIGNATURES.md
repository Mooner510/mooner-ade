# 릴리스 파일 서명

서명은 오프라인에서 릴리스 파일을 확인한 뒤 수행한다. 공개키 목록에는 운영자가 제공한 Ed25519 주 키와 예비 키의 PEM 공개키만 넣는다. 운영자의 개인키는 릴리스 디렉터리·저장소·CI 밖에 보관하며 오프라인 백업의 복구를 시험한다.

오프라인 작업 폴더에 검토한 빌드의 파일을 모은다. 플러그인은 같은 릴리스의 SHA256SUMS와 plugin-releases.json이 필요하다. 기존 v1 산출물은 versions.json으로 식별할 수 있다. 본체 릴리스에는 SHA256SUMS가 없을 수 있으므로 운영자가 신뢰하는 빌드에서 별도로 준비한 SHA256SUMS를 제공한다. 이미 게시된 출처에서 받은 zip과 그 출처가 제공하는 체크섬만으로는 제작자를 확인할 수 없다.

```sh
node scripts/sign-release.mjs <v버전> <릴리스-폴더> <오프라인-개인키-파일>
```

결과는 자산 이름 뒤에 .sig가 붙는 JSON 파일이다. issued는 Unix 초, signature는 Ed25519 서명의 표준 base64다. 검증기는 내려받은 바이트 수와 해시, 요청한 종류·id·버전·플랫폼·variant를 사용해 UTF-8 진술문을 다시 만든다. 각 필드와 마지막 줄은 LF로 끝난다. 운영자가 서명 파일을 자산과 함께 옮긴다.

관찰 기간에는 누락·불일치·공개키 대기도 로그와 설정에 기록한다. 기존 체크섬과 플랫폼 검사는 유지한다. 운영용 키 두 개와 복구 절차를 확인하고 한 번의 실제 릴리스에서 GitHub 및 Hub 경로, 플랫폼별 zip의 검증과 키 교체를 확인한 뒤 자동 업데이트 정책 전환을 별도로 결정한다. 전면 적용은 이전 클라이언트 호환 기간, 수동 다운그레이드 승인, 가장 높은 검증 버전의 저장과 로컬 zip 처리까지 검증한 뒤 결정한다. 키 교체 시 기존 키로 새 공개키 목록을 담은 앱을 서명하며 예비 키를 배포한 뒤 이전 키를 제거한다.
