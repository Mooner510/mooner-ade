# Claude Code 구독 한도 기여도 정밀 측정 조사 보고서

**기준일:** 2026년 11월 12일  
**목표:** 특정 Claude Code 세션의 5시간·주간 한도 소비율을 소수점 단위까지 측정

## 1. 최종 조사 결과

**현재 공개적으로 확인 가능한 방법으로는 세션별 실제 기여율을 소수점까지 정확하게 산출한다고 보장할 수 없다.**

그러나 서버 사용률의 정밀도와 과거 사용 기록에 따라 측정 정확도를 개선할 수 있다.

| 데이터 소스 | 실제 관측된 정밀도 | 평가 |
|---|---|---|
| Claude `/usage` 화면 | 정수 1% 단위 | 정밀 측정 불가 |
| OAuth `/api/oauth/usage` | 대체로 정수 1% 단위 (`17.0`도 정수 수준) | 정밀 측정 불가 |
| Claude Code Statusline | 숫자형이지만 2026년 실측에서 주로 정수 | 원본 확인 필요 |
| Agent SDK `unifiedWindows` | `0.49`처럼 0~1 비율, 관측상 1% 단위 | 소수 비율이라고 정밀한 것은 아님 |
| 실제 API 응답의 `anthropic-ratelimit-unified-*` 헤더 | 과거에는 다자리 소수, 최근에는 정수 % 수준으로 양자화된 사례 | 최우선 추가 검증 대상 |
| Claude 웹 응답의 `message_limit.windows` | 0~1 비율 | 실제 소수점 정밀도 미확인 |
| JSONL / OpenTelemetry | 요청별 토큰은 정수 단위 | 실제 한도 환산식은 비공개 |

### 핵심 증거

- **2026-10-11, Anthropic Issue #101232:** 28,821건의 사용률 기록에서 소수 부분이 전혀 나타나지 않았다는 실측 보고.
- **2026-10-25, Issue #104967:** 개별 API 요청이 구독 한도의 몇 %p를 소비했는지 반환하는 기능이 아직 필요하다는 요청. 동일한 사용량으로도 모델별 차감 비율이 달랐다는 실험 결과 포함.
- **2026-10-29, Issue #105890:** 응답 헤더와 OAuth 사용률 API의 반올림 방식 차이로 98%와 99%가 동시에 표시된 사례.
- **2025-12-01, Issue #12829:** 실제 HTTP 응답 헤더에서 `0.018416969696969696`처럼 높은 정밀도의 원본 값이 확인됨. 다만 2026년에도 같은 정밀도가 유지되는지는 확인되지 않음.

## 2. 정수 %가 갖는 측정 한계

실제 사용량이 다음과 같아도:

| 시점 | 실제 사용률 | 반올림 표시 |
|---|---:|---:|
| 세션 시작 | 12.20% | 12% |
| 세션 종료 | 12.65% | 13% |
| 실제 기여도 | +0.45%p | 관측값 +1%p |

반대로 12.10% → 12.40%는 실제로 0.30%p를 소비했지만 화면에는 12% → 12%로 표시될 수 있다.

따라서:

- 한도 사용률이 변하지 않아도 실제 소비량은 0이 아닐 수 있다.
- 정수 단위의 전후 사용률 차이는 일반적으로 약 ±1%p의 양자화 오차가 발생할 수 있다.
- 여러 번 관측한다고 해서 1% 미만의 개별 소비량을 확정할 수는 없다.
- 한도 초기화, 다른 세션 활동, 서버 반영 지연은 별도의 오차 요인이다.

## 3. 가장 신뢰할 만한 구현 방법

### 1순위 — 실제 응답 헤더의 정밀도 확인

Claude Code의 구독 로그인 응답에서 다음 헤더를 조사한다.

```text
anthropic-ratelimit-unified-5h-utilization
anthropic-ratelimit-unified-7d-utilization
anthropic-ratelimit-unified-5h-reset
anthropic-ratelimit-unified-7d-reset
```

활용할 프로젝트:

- [claude-rate-monitor](https://github.com/nsanden/claude-rate-monitor) — 헤더 조회 구현
- [claude-usage](https://github.com/samsonites89/claude-usage) — 최소 요청으로 한도 상태 조회
- [Claude Code Statusline 문서](https://code.claude.com/docs/en/statusline) — CLI가 전달하는 한도 정보

**검증 절차**

1. 헤더 또는 Statusline의 실제 원본 숫자를 반올림하지 않고 저장한다.
2. 동일한 5시간 구간에서 여러 요청을 수행한다.
3. 값이 `0.01`, `0.02`처럼만 변하는지, `0.012345`처럼 세밀하게 변하는지 확인한다.
4. 여러 차례 변화를 관측하여 실질적인 측정 분해능을 확인한다.

**판단 기준**

- 실제 원본이 다자리 소수라면 단독 세션의 전후 기여도를 더 정밀하게 측정할 가능성이 있다.
- 원본 자체가 `0.01` 단위라면 소수점을 추가 표시해도 정밀도는 개선되지 않는다.
- API 응답 헤더는 공식 공개 계약이 아니므로 버전별 검증이 필요하다.

### 2순위 — 단독 실행 세션의 실측 기여도

현재 확인된 가장 신뢰할 만한 방식이다.

필요 데이터:

- 계정 전체의 5시간·주간 사용률
- 해당 세션의 시작·종료 시각
- 한도 초기화 시각
- 같은 기간의 다른 Claude 사용 여부

실제 계산:

```text
실측 기여도(%p) =
    단독 세션 종료 후 사용률
  - 단독 세션 시작 전 사용률
```

초기화가 없고 다른 사용이 없으며 서버 집계가 안정화됐을 때만 사용한다.

정수 사용률만 있다면 단일값을 정확한 기여도라고 주장하지 말고 **관측 증가량과 오차 범위**를 함께 출력한다.

### 3순위 — 세션 사용량 기반 통계적 추정

실제 구독 사용률이 정수로만 제공된다면 요청별 데이터를 수집해 한도 소비 모델을 구축한다.

**데이터 수집**

- [Claude Code OpenTelemetry](https://code.claude.com/docs/en/monitoring-usage)
- [ccusage](https://github.com/ccusage/ccusage)

필요 필드:

```text
session_id
request_id
timestamp
model
input_tokens
output_tokens
cache_read_tokens
cache_creation_tokens
estimated_cost_usd
```

**추정 알고리즘**

1. 단독 실행 구간에서 정수 사용률 변화와 토큰 종류별 사용량을 확보한다.
2. 다수의 구간을 누적해 모델별 가중치와 한도 환산 계수를 추정한다.
3. 이 환산 모델을 각 세션의 요청 기록에 적용한다.
4. 5시간과 주간 한도를 별도로 학습한다.
