# 로컬 ADE 사용 안내

무너에이드는 터미널과 에이전트 CLI 중심의 macOS·Windows 데스크톱 앱입니다. 설치·실행 명령은 [README](../README.md), 실제 검증 상태는 [VERIFICATION](VERIFICATION.md)이 기준입니다.

## 실행 환경

Node 24.21.0 이상, pnpm 11.27.1, Git이 필요합니다. `pnpm install --frozen-lockfile` 후 `pnpm start`로 실행합니다. 앱은 실행할 때마다 로컬 서버의 새 접속 토큰을 받아 HttpOnly/SameSite=Strict 쿠키로 교환하며, 토큰은 디스크에 저장하지 않습니다.

`pnpm dev`는 웹 HMR, 서버 자동 재시작과 preload 갱신을 지원합니다. 터미널은 서버와 분리된 PTY 호스트에 있으므로 서버가 바뀌는 동안에도 유지됩니다. Electron 메인 코드·PTY 호스트를 바꿨다면 앱을 직접 재시작하세요. 개발 파일 감시 오류가 나면 로그를 확인하고 수동 재시작하세요.

macOS 첫 실행은 `apps/desktop/dist/electron-<version>/MoonerADE.app`을 생성하고 로컬 서명합니다. Windows는 `apps/desktop/dist/electron-<version>-win32-<arch>/MoonerADE.exe`로 런타임을 복사합니다. 원본 Electron은 유지하며 별도 디스크 공간이 필요합니다. 배포용 앱은 `pnpm package`로 만듭니다(설치 프로그램은 생성하지 않습니다).

## 화면과 작업

- 왼쪽 프로젝트 사이드바에서 프로젝트·탭을 선택합니다. Shift+드래그로 분할 pane을 별도 탭으로 떼어낼 수 있습니다. 폴더 아래 ＋ 또는 상단 새 탭 버튼으로 터미널을 추가합니다.
- 빈 상태에서는 사용자 홈 폴더를 엽니다. **프로젝트 열기**에서 경로를 입력하거나, 데스크톱 폴더 선택·GitHub 클론을 사용할 수 있습니다.
- 터미널·Claude Code·Codex 실행을 선택합니다. Claude/Codex CLI는 별도 설치와 로그인이 필요합니다. CLI의 파일 수정·명령 실행 권한은 CLI 자체 설정과 승인 화면을 따릅니다.
- 오른쪽 **변경사항 Diff 패널**에서 HEAD 대비 파일과 읽기 전용 inline diff를 확인합니다. 기본적으로 첫 파일만 펼치며 전체 펼치기·접기·큰 화면 diff를 제공합니다.
- 오른쪽 패널 자리는 **변경사항 Diff**, **오류 목록**, **피드백 요청**이 나눠 씁니다. 하나를 열면 나머지는 가려지고(피드백 요청은 상단 바 버튼, `mod+Alt+F`, 명령 팔레트로 엽니다), 프로젝트가 없는 시작 화면에도 피드백 요청 버튼이 있습니다. 앱 창을 캡쳐해 개선 요청을 쓰고 개발자 Hub로 보내는 기능이며 구조는 [아키텍처](ARCHITECTURE.md#피드백-요청)에 있습니다.
- pane·패널 헤더의 아이콘 버튼은 마우스를 올리면 앱 스타일 툴팁이 뜨고(닫기 X는 툴팁 없음), 쓸 수 없는 버튼은 흐리게 두지 않고 숨깁니다: Diff 패널의 모두 펼치기·모두 접기는 변경이 있을 때만, 오류 패널의 모두 지우기는 오류가 있을 때만, 터미널의 Chat 전환은 Claude이고 SSH가 아니며 승인 대기·작업 중이 아닐 때만 나옵니다.
- 하단 상태바의 서버 연결 표시는 정상일 때 아무것도 보이지 않습니다. 연결이 `연결됨`이 아닐 때만(시작 직후 "연결 대기", 끊기면 "연결 끊김 · 재연결 중") 글자와 함께 나타납니다.
- 파일 편집·탐색·검색·스테이징·커밋 화면은 없습니다. 커밋은 터미널이나 에이전트에서 하세요.
- 프로젝트가 Git 저장소가 아니면 바로 아래의 저장소를 탐색합니다. 여러 저장소를 찾으면 Diff 패널에서 Git 대상 저장소를 선택하며 터미널의 루트는 열린 상위 폴더입니다.
- 작업 중·응답 필요·완료 상태는 Claude Code/Codex가 직접 보내는 OSC 7501 상태 보고로 표시합니다. 서버가 지원 질의에 응답하고 마지막 상태를 보관해 창 새로고침·재연결에도 복원합니다. 일반 출력·제목·출력 없는 시간을 작업 상태로 추측하지 않습니다. 상태 보고가 없는 세션의 질문/승인 표시는 화면 문구를 보조적으로 확인합니다. 제공자 권한 검사를 대체하지 않습니다.
- Claude Code는 v2.1.295 이상이 필요합니다. 지원 응답을 받기 전에 시작된 Claude 세션은 CLI를 다시 실행해야 상태 보고가 켜집니다. 상태 보고를 보내지 않는 구버전·환경에서는 작업 중 표시를 추측해서 켜지 않습니다.
- SSH로 접속한 호스트의 Claude Code는 그 호스트에 있는 Claude의 세션 파일(`~/.claude/sessions/<pid>.json`의 busy/idle 상태)과 대화 기록을 읽어 작업 중 표시와 Cache 타이머를 채웁니다. 터미널이 쓰는 ssh 설정(키·포트·점프 호스트)으로 4초마다 비대화식 ssh를 한 번 실행하므로, 키나 에이전트처럼 비밀번호 입력 없이 접속되어야 하고 호스트는 POSIX(`sh`)여야 합니다. 접속할 수 없으면 30초 간격으로 다시 시도하고 아무것도 표시하지 않습니다. 호스트에 Claude가 여러 개 떠 있으면 하나뿐일 때, 또는 화면에 폴더 이름이 보이는 하나만 이 터미널의 것으로 봅니다(구분할 수 없으면 읽지 않습니다). OSC 7501·진행 표시가 오면 그쪽이 우선이고, 원격 tmux에 별도 설정을 하지 않아도 동작합니다. idle compaction 시각은 원격에서 표시하지 않습니다.
- tmux 안(예: SSH 원격의 tmux)에서는 tmux가 OSC 7501 지원 질의를 버리므로 Claude가 상태 보고를 켜지 않습니다. 대신 Claude가 tmux 통과 형식으로 보내는 진행 표시(OSC 9;4)를 보조 신호로 씁니다(위의 원격 세션 파일을 읽을 수 없을 때를 위한 대안입니다). 에이전트가 식별된 터미널에서만, 같은 터미널이 OSC 7501을 보낸 적이 없을 때만 씁니다. 진행 표시로는 작업 중과 완료만 알 수 있으며, 질문/승인은 화면 문구로 확인합니다. Claude를 실행하는 쪽(원격)에 다음 두 설정이 모두 필요합니다.

  ```sh
  # ~/.tmux.conf — tmux 통과 형식의 출력을 바깥 터미널로 전달
  set -g allow-passthrough on
  # ~/.bashrc 등 — Claude가 진행 표시를 보내도록 함 (SSH는 이 환경 변수를 넘기지 않음)
  export ConEmuANSI=ON
  ```

  tmux 설정을 바꾼 뒤에는 `tmux source-file ~/.tmux.conf`로 다시 읽고, 환경 변수를 넣은 뒤 연 셸에서 Claude를 다시 실행하세요. tmux에서는 제목도 전달되지 않으므로, Claude를 종료한 뒤에도 SSH 접속이 끝날 때까지 터미널이 Claude로 표시될 수 있습니다.

## 단축키

`mod`는 macOS에서 ⌘, 그 외에는 Ctrl입니다. 명령 팔레트(`mod+Shift+P` 또는 F1)에서 명령을 검색할 수 있습니다.

| 키 | 동작 |
|---|---|
| `mod+Alt+O` / `mod+Alt+W` | 프로젝트 열기 / 닫기 |
| `mod+Alt+1…9` | 프로젝트 선택 (9는 마지막) |
| `mod+Alt+]` / `mod+Alt+[` | 다음 / 이전 프로젝트 |
| `mod+Alt+B` | 사이드바 접기/펼치기 |
| `mod+Shift+T` / `Alt+T` | 새 터미널 탭 |
| `mod+Shift+N` | 새 탭에서 CLI 실행 선택 |
| `mod+Shift+W` / `Alt+W` | 탭 / 포커스 pane 닫기 |
| `Alt+]` / `Alt+[` / `Alt+1…9` | 다음 / 이전 / N번째 탭 |
| `mod+Shift+Enter` | pane 최대화 전환 |
| `Alt+Shift+방향키` / `Cmd(Ctrl)+Shift+방향키` | pane 포커스 이동 (Shift 없는 Alt·Cmd+방향키는 터미널로 전달: 단어·줄 이동) |
| `mod+Shift+G` / `mod+,` | Diff 패널 / 설정 |
| `mod+Alt+F` | 피드백 요청 패널 전환 |
| `mod+Alt+Shift+F` | 피드백용 화면 캡쳐 시작 |

터미널에 포커스가 있을 때 일반 Ctrl 조합은 셸·CLI로 전달합니다. 분할은 pane의 도구 버튼 또는 명령 팔레트를 사용하세요. 과거 안내의 Ctrl+D 좌우 분할은 현재 터미널 입력 정책과 일치하지 않습니다.

## 데이터와 복구

기본 경로는 [환경 변수](../ENVIRONMENT_VARIABLES.md)에 있습니다. 최근 프로젝트·화면 배치·설정과 터미널별 에이전트 세션 기록이 저장됩니다. 경로나 세션 정보가 들어 있으므로 데이터 폴더를 공유하지 마세요.

열린 프로젝트·공용 설정은 `app-state.json`, 최근 목록은 `recent.json`, 프로젝트별 레이아웃과 저장소 worktree 설정은 `<projectId>/state.json`입니다. 이전 버전이 만든 `<projectId>/runs/`(서버 SDK 실행 기록)는 더 이상 읽지 않으며 필요 없으면 지워도 됩니다.

창 새로고침은 기존 서버의 PTY에 다시 붙고 최근 터미널 출력 256 KiB를 재생합니다. 앱을 직접 종료했다가 다시 켜면 저장된 레이아웃에 새 셸을 열며 예전 셸 프로세스나 명령 실행을 복원하지 않습니다(Claude 대화는 `claude --resume`으로 이어집니다). 서버는 종료 직전에 각 Claude의 세션 ID를 한 번 더 기록합니다.

자동 업데이트의 재시작은 다릅니다. 터미널은 앱과 분리된 PTY 호스트 프로세스가 갖고 있어서, 업데이트로 앱과 서버가 내려가도 셸과 그 안의 명령·에이전트는 계속 실행됩니다. 새 버전의 서버가 같은 호스트에 다시 붙어 열려 있던 프로젝트의 터미널을 같은 ID로 넘겨받고, 그사이 출력은 호스트가 모아 둔 최근 256 KiB에서 재생합니다. 그래서 업데이터는 터미널 작업을 기다리지 않고, 재시작을 넘기지 못하는 작업(플러그인 세션 등)만 기다립니다.

- 호스트는 설치 폴더 밖, `<userData>/pty-host/<내용 해시>/`의 복사본(Node 실행 파일, 호스트 소스, node-pty·ConPTY)에서 실행됩니다. 설치 폴더 파일을 잡고 있지 않으므로 Windows 업데이트의 폴더 교체가 막히지 않습니다. 내용이 같은 복사본은 다시 쓰고, 쓰지 않는 복사본은 다음 실행 때 지웁니다. 플러그인이 터미널에 넣는 도구도 이 복사본의 Node로 실행합니다.
- 앱은 호스트를 분리된 프로세스로 띄우고 `<userData>/pty-host/pty-host.json`(사용자만 읽을 수 있음)에 연결 정보를 남깁니다. 다음 실행은 이 파일로 살아 있는 호스트를 찾아 다시 씁니다.
- 수명: 앱을 직접 종료하면 터미널도 끝납니다. 업데이트 재시작이면 5분, 앱이 비정상 종료되면 2분 동안 새 앱을 기다린 뒤 터미널을 정리합니다. 터미널도 연결된 서버도 없으면 바로 끝납니다. 기록은 `<userData>/pty-host/pty-host.log`에 남습니다.
- 앱과 호스트는 연결할 때 버전을 확인합니다. 새 앱이 이전 호스트와 맞지 않으면 그 터미널을 몰래 끄지 않고 새 호스트로 시작하며, 이전 터미널은 넘겨받지 못했고 몇 분 뒤 정리된다고 알립니다.
- 호스트를 띄우지 못하거나 실행 중에 호스트가 끝나면 이후 터미널은 예전처럼 서버 프로세스 안에서 열리고, 이때는 업데이트가 터미널 작업을 다시 기다립니다.

ADE의 Claude Code/Codex 실행 메뉴와 터미널에 직접 입력한 `claude`·`codex` 모두 각각의 대화 ID로 복구합니다. bash/zsh/sh/dash/fish/PowerShell에서 사용자 시작 설정을 먼저 읽고 ADE 셸에만 실행 함수를 연결합니다. 셸 히스토리는 비어 시작하지 않도록 따로 맞춥니다(`terminal-sessions.js`). zsh는 macOS의 `/etc/zshrc`가 세션 폴더(`ZDOTDIR`)를 기준으로 `HISTFILE`을 정해 위쪽 화살표 기록과 자동완성이 비던 것을, 사용자 `.zshrc`를 읽기 전에 사용자 `ZDOTDIR`(없으면 홈)의 `.zsh_history`로 되돌려 막습니다. 사용자가 `HISTFILE`을 직접 정했다면 그 값이 남습니다. PowerShell은 PSReadLine 2.1 이상에서 히스토리 예측이 꺼져(`None`) 있을 때만 `History`로 켭니다. 프로젝트 데이터의 `terminal-sessions/<terminalId>/`에 Claude의 `SessionStart` 훅 기록 또는 Codex의 터미널별 실행 로그를 보관합니다. Claude의 `/clear`·`/resume`, Codex의 새 대화·복구로 ID가 바뀌면 다음 복구에 반영합니다. ID가 없는 기존 기록은 `claude --resume` / `codex resume` 선택 화면을 엽니다. 최근 대화를 임의로 선택하지 않습니다.

Codex는 다른 터미널과 기록이 섞이지 않도록 이 실행에만 `--no-daemon`과 `log_dir`를 지정합니다. 세션 추적은 Codex 0.163.0의 root session 시작 로그 형식과 Claude 2.1.304의 `SessionStart` 훅을 기준으로 합니다. Codex는 `--no-daemon`을 지원해야 하며, 로그 형식이 바뀌거나 Claude 훅이 비활성화되어 ID를 확인하지 못하면 자동 복구 대신 선택 화면이 필요합니다. 전역 CLI 설정 파일은 변경하지 않습니다.

절대 경로·`command claude`·`env codex` 등으로 함수를 우회하거나, SSH/중첩 셸·tmux에서 실행하면 ID 추적이 보장되지 않습니다. 지원하지 않는 셸도 직접 실행 추적 대상이 아닙니다. 업데이트 전에 이미 열린 셸에는 함수가 없으므로 새 터미널에서 실행하세요.

프로젝트당 터미널 32개, 전체 128개 제한이 있습니다. 파일 감시 실패 시 서버는 계속 동작하며 현재 프로젝트의 Git 상태를 설정한 Diff 새로고침 주기(기본 3초)로 비교합니다. 백그라운드 프로젝트는 다시 선택할 때 갱신합니다.

터미널에 붙여 넣은 이미지는 데이터 폴더의 `paste/`에 저장되며 24시간 뒤 또는 전체 256 MiB를 넘으면 오래된 것부터 지웁니다.

## Worktree와 안전 범위

공유 경로가 기본입니다. 멀티 저장소 프로젝트에서 저장소별로 worktree를 명시적으로 켤 때만 생성합니다. 원본 통합은 fast-forward만 지원하고, dirty 상태의 제거와 대상 경로의 변경을 거절합니다. 통합 전에 터미널에서 변경을 커밋하세요. 브랜치는 자동 삭제하지 않습니다.

로컬 서버가 실행한 Git은 저장소의 fsmonitor와 hooks를 끕니다. 터미널에서 직접 실행하는 Git과 에이전트 CLI의 Git은 사용자의 환경을 따릅니다. 프로젝트 루트 경로 검사는 터미널과 에이전트를 격리하지 않습니다. [보안 제한](SECURITY_REVIEW.md)을 참고하세요.
