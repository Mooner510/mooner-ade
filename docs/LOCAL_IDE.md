# 로컬 ADE 사용 안내

무너에이드는 터미널과 에이전트 CLI 중심의 macOS·Windows 데스크톱 앱입니다. 설치·실행 명령은 [README](../README.md), 실제 검증 상태는 [VERIFICATION](VERIFICATION.md)이 기준입니다.

## 실행 환경

Node 24.21.0 이상, pnpm 11.27.1, Git이 필요합니다. `pnpm install --frozen-lockfile` 후 `pnpm start`로 실행합니다. 앱은 실행할 때마다 로컬 서버의 새 접속 토큰을 받아 HttpOnly/SameSite=Strict 쿠키로 교환하며, 토큰은 디스크에 저장하지 않습니다.

`pnpm dev`는 웹 HMR, 서버 자동 재시작과 preload 갱신을 지원합니다. 터미널은 서버와 분리된 PTY 호스트에 있으므로 서버가 바뀌는 동안에도 유지됩니다. Electron 메인 코드·PTY 호스트를 바꿨다면 앱을 직접 재시작하세요. 개발 파일 감시 오류가 나면 로그를 확인하고 수동 재시작하세요.

macOS 첫 실행은 `apps/desktop/dist/electron-<version>/MoonerADE.app`을 생성하고 로컬 서명합니다. Windows는 `apps/desktop/dist/electron-<version>-win32-<arch>/MoonerADE.exe`로 런타임을 복사합니다. 원본 Electron은 유지하며 별도 디스크 공간이 필요합니다. 배포용 앱은 `pnpm package`로 만듭니다(설치 프로그램은 생성하지 않습니다).

## 화면과 작업

- 왼쪽 프로젝트 사이드바에서 프로젝트·탭을 선택합니다. Shift+드래그로 분할 pane을 별도 탭으로 떼어낼 수 있습니다. 폴더 아래 ＋ 또는 상단 새 탭 버튼으로 터미널을 추가합니다. 사이드바의 탭·pane 줄에 포커스한 채 `F2`는 이름 바꾸기, `Delete`는 닫기(X 버튼처럼 설정과 관계없이 먼저 확인), `Alt+↑/↓`는 순서 이동이고, `↑/↓`·`←/→`로 줄 사이를 다닙니다(아래 [키보드로 오가기](#키보드로-오가기)).
- 빈 상태에서는 사용자 홈 폴더를 엽니다. **프로젝트 열기**에서 경로를 입력하거나, 데스크톱 폴더 선택·GitHub 클론을 사용할 수 있습니다.
- 사이드바의 프로젝트를 우클릭하면 **탐색기(Finder)에서 폴더 열기**, **파일 열기…**(프로젝트 파일을 이름으로 찾아 고름), 그리고 이 컴퓨터에서 감지된 편집기로 프로젝트 열기(VS Code·Insiders·Cursor·Windsurf·VSCodium·Zed·JetBrains 제품)를 고를 수 있습니다. 편집기는 설치 폴더와 PATH에서 찾으며 서버가 직접 실행합니다. 마지막에 쓴 편집기가 목록 맨 위에 옵니다.
- Chat 모드 답변의 `[[file:src/app.ts:42]]` 형식은 파일 아이콘이 붙은 칩으로 보이고(폴더는 `[[file:src/]]`), 누르면 링크처럼 먼저 물은 뒤 편집기·탐색기 위치 열기·경로 복사 중에서 고릅니다. 프로젝트 안의 경로는 프로젝트(워크트리 채팅은 그 워크트리) 기준 상대 경로로 씁니다. 프로젝트 밖(형제 저장소 등)도 칩으로 쓰며, 프로젝트 기준 `[[file:../other/a.zip]]`나 절대 경로를 열 수 있습니다. 열기만 하고 읽거나 쓰지 않으며, 네트워크 경로(`\\서버\공유`)는 거절합니다. 백틱은 사용자가 글자로 적어 달라고 할 때만 씁니다. 새로 만든 Claude·Codex 채팅은 첫 메시지 때 이 형식을 쓰라는 안내를 시스템 프롬프트로 받습니다(`chat-prompt.js`). 시스템 프롬프트를 바꾸면 대화 전체가 프롬프트 캐시를 놓치므로 이미 세션이 있던 채팅에는 넣지 않고, Cursor는 시스템 프롬프트 채널이 없어 적용되지 않습니다(경로가 칩이 되지 않고 평문으로 보임).
- 터미널·Claude Code·Codex 실행을 선택합니다. Claude/Codex CLI는 별도 설치와 로그인이 필요합니다. CLI의 파일 수정·명령 실행 권한은 CLI 자체 설정과 승인 화면을 따릅니다.
- 상단 **Git** 버튼(`mod+Shift+G`)은 커밋하지 않은 변경의 `+/−` 줄 수만 보여 주고, 누르면 아래에서 **Git 커밋 그래프** drawer가 올라옵니다(X 또는 `Shift+Esc`로 닫음). IntelliJ Git 로그와 같은 규칙(layout index로 정한 열, 브랜치 이름으로 정한 색, 30행 이상 긴 선의 화살표, 커밋 날짜순/위상 정렬)으로 그리고, 브랜치 패널·필터(텍스트·브랜치·사용자·날짜·경로)·변경 파일·커밋 세부 정보·diff 미리 보기를 둡니다. 커밋 우클릭과 브랜치 메뉴에서 체크아웃, 새 브랜치·태그, 머지, 리베이스, 체리픽, 되돌리기, 리셋, 커밋 실행 취소·메시지 편집·삭제·스쿼시, 대화형 리베이스, push, 업데이트, fetch를 실행하고, 충돌은 충돌 대화상자와 상단 진행 막대(계속·건너뛰기·중단)로 처리합니다. 파일을 더블클릭하면 편집기 영역에 그 커밋의 diff 탭이 열립니다. 보기·그래프 옵션은 설정 > Git에서도 바꿉니다.
- 오른쪽 패널 자리는 **오류 목록**, **피드백 요청**, 상단 바 플러그인이 나눠 씁니다. 하나를 열면 나머지는 가려지고(피드백 요청은 상단 바 버튼, `mod+Alt+F`, 명령 팔레트로 엽니다), 프로젝트가 없는 시작 화면에도 피드백 요청 버튼이 있습니다. 앱 창을 캡쳐해 개선 요청을 쓰고 개발자 Hub로 보내는 기능이며 구조는 [아키텍처](ARCHITECTURE.md#피드백-요청)에 있습니다.
- pane·패널 헤더의 아이콘 버튼은 마우스를 올리면 앱 스타일 툴팁이 뜨고(닫기 X는 툴팁 없음), 쓸 수 없는 버튼은 흐리게 두지 않고 숨깁니다: 오류 패널의 모두 지우기는 오류가 있을 때만, 터미널의 Chat 전환은 Claude이고 SSH가 아니며 승인 대기·작업 중이 아닐 때만 나옵니다.
- 하단 상태바의 서버 연결 표시는 정상일 때 아무것도 보이지 않습니다. 연결이 `연결됨`이 아닐 때만(시작 직후 "연결 대기", 끊기면 "연결 끊김 · 재연결 중") 글자와 함께 나타납니다.
- 상단 바의 **프로젝트 파일 트리** 버튼으로 파일 트리를 열어 파일·폴더를 만들고 옮기고 복사하고 지웁니다. 파일을 열면 ADE 편집기(Monaco)에서 고치고 `mod+S`로 저장합니다. 편집 중에 바깥(에이전트·다른 편집기)에서 파일이 바뀌면 덮어쓰지 않고 충돌로 알립니다(고치지 않은 파일은 다시 읽습니다). Git 커밋 그래프에서 연 diff 탭은 읽기 전용입니다.
- 파일 내용 전체 검색과 스테이징·커밋 화면은 없습니다(파일 트리에서 글자를 치면 이름으로만 이동합니다). 커밋은 터미널이나 에이전트에서 하고, 기록 확인과 브랜치 작업은 Git 커밋 그래프에서 합니다.
- 프로젝트가 Git 저장소가 아니면 바로 아래의 저장소를 탐색합니다. 여러 저장소를 찾으면 Git 커밋 그래프 머리줄에서 Git 대상 저장소를 선택하며 터미널의 루트는 열린 상위 폴더입니다.
- 작업 중·응답 필요·완료 상태는 Claude Code/Codex가 직접 보내는 OSC 7501 상태 보고로 표시합니다. 서버가 지원 질의에 응답하고 마지막 상태를 보관해 창 새로고침·재연결에도 복원합니다. 일반 출력·제목·출력 없는 시간을 작업 상태로 추측하지 않습니다. 상태 보고가 없는 세션의 질문/승인 표시는 화면 문구를 보조적으로 확인합니다. 제공자 권한 검사를 대체하지 않습니다.
- Claude Code는 v2.1.295 이상이 필요합니다. 지원 응답을 받기 전에 시작된 Claude 세션은 CLI를 다시 실행해야 상태 보고가 켜집니다. 상태 보고를 보내지 않는 구버전·환경에서는 작업 중 표시를 추측해서 켜지 않습니다.
- SSH로 접속한 호스트의 Claude Code는 그 호스트에 있는 Claude의 세션 파일(`~/.claude/sessions/<pid>.json`의 busy/idle 상태)과 대화 기록을 읽어 작업 중 표시와 Cache 타이머를 채웁니다. 터미널이 쓰는 ssh 설정(키·포트·점프 호스트)으로 4초마다 비대화식 ssh를 한 번 실행하므로, 키나 에이전트처럼 비밀번호 입력 없이 접속되어야 하고 호스트는 POSIX(`sh`)여야 합니다. 접속할 수 없으면 30초 간격으로 다시 시도하고 아무것도 표시하지 않습니다. 호스트에 Claude가 여러 개 떠 있으면 하나뿐일 때, 또는 화면에 폴더 이름이 보이는 하나만 이 터미널의 것으로 봅니다(구분할 수 없으면 읽지 않습니다). OSC 7501·진행 표시가 오면 그쪽이 우선이고, 원격 tmux에 별도 설정을 하지 않아도 동작합니다. idle compaction 시각은 원격에서 표시하지 않습니다.
- tmux 안(예: SSH 원격의 tmux)에서는 tmux가 OSC 7501 지원 질의를 버리므로 Claude가 상태 보고를 켜지 않습니다. 대신 Claude가 tmux 통과 형식으로 보내는 진행 표시(OSC 9;4)를 보조 신호로 씁니다(위의 원격 세션 파일을 읽을 수 없을 때를 위한 대안입니다). 에이전트가 식별된 터미널에서만, 같은 터미널이 OSC 7501을 보낸 적이 없을 때만 씁니다. 진행 표시로는 작업 중과 완료만 알 수 있으며, 질문/승인은 화면 문구로 확인합니다. Claude를 실행하는 쪽(원격)에 다음 두 설정이 모두 필요합니다.

  ```sh
  # ~/.tmux.conf — tmux 통과 형식의 출력을 바깥 터미널로 전달
  set -g allow-passthrough on
  # ~/.bashrc 등 — Claude가 진행 표시를 보내도록 함 (SSH는 이 환경 변수를 넘기지 않음)
  export ConEmuANSI=ON
  ```

  tmux 설정을 바꾼 뒤에는 `tmux source-file ~/.tmux.conf`로 다시 읽고, 환경 변수를 넣은 뒤 연 셸에서 Claude를 다시 실행하세요. tmux에서는 제목도 전달되지 않으므로, Claude를 종료한 뒤에도 SSH 접속이 끝날 때까지 터미널이 Claude로 표시될 수 있습니다.

## 선택한 내용을 채팅으로 보내기

편집기·터미널·파일 트리·Git 그래프에서 고른 것을 채팅 입력창에 채웁니다(보내지는 않음). `mod+Shift+L`(설정 › 단축키 "선택 영역을 채팅으로 보내기"), 명령 팔레트, 또는 각 위치의 우클릭 메뉴 **채팅으로 보내기**로 실행합니다. 받는 채팅과 글 형식은 [채팅 기능 정리 §4](../CHAT_MODE_FEATURES.md#4-메시지-입력)에 있습니다.

- **ADE 편집기**: 선택한 줄이 `@src/a.ts#10-20`으로 들어갑니다(선택이 없으면 `@src/a.ts`). 우클릭 메뉴(복사·붙여넣기 아래)에도 있습니다. Monaco의 `Ctrl/⌘+Shift+L`(일치 항목 모두 선택)은 이 키가 가져가므로, 같은 일은 `Ctrl+F2`(모든 항목 변경)로 합니다. 경로는 디스크의 파일을 가리키므로, 저장하지 않은 편집이 있으면 줄 번호가 디스크와 다를 수 있습니다.
- **diff 탭·Git 그래프의 diff 미리 보기**: 고른 줄은 그 버전(커밋, 변경 전/후)의 코드 블록으로, 고르지 않으면 그 파일의 패치로 들어갑니다(300줄이 넘으면 위치와 `git show`/`git diff` 명령만). 경로는 Git 그래프에서 고른 저장소 기준입니다.
- **터미널**: 마우스로 고른 출력이 코드 블록으로 들어갑니다(아무것도 고르지 않았으면 먼저 고르라는 안내만). 설정의 "우클릭으로 붙여넣기"가 꺼져 있으면(기본) 터미널 우클릭에 복사·붙여넣기·채팅으로 보내기 메뉴가 뜨고, 켜져 있으면 우클릭은 전처럼 복사/붙여넣기라 단축키나 팔레트로 보냅니다. 터미널에 포커스가 있어도 `Ctrl+Shift+L`은 앱이 가져갑니다(셸에는 `Ctrl+L`과 같은 ^L이라 `Ctrl+L`을 쓰면 됨).
- **파일 트리**: 고른 파일·폴더가 `@경로`(폴더는 `@폴더/`)로 들어갑니다. 트리에서 복사(`mod+C`)·잘라내기(`mod+X`)하면 고른 항목의 절대 경로가 시스템 클립보드에도 들어가고, 그대로 채팅 입력창에 붙여넣으면 `@경로`가 들어갑니다.
- **Git 커밋**: 커밋 우클릭 메뉴나 커밋 목록에 포커스한 채 단축키로, 고른 커밋의 해시·제목과 패치가 들어갑니다.
- **복사해서 붙여넣기**: 편집기에서 여러 줄을(또는 선택 없이 한 줄을) 복사해 채팅 입력창에 붙여넣어도 내용 대신 `@경로#줄`이 들어갑니다. 원문은 `Ctrl/⌘+Shift+V`, 또는 붙여넣은 직후 입력창 위의 **원문으로 붙여넣기**. 설정 › 채팅 › 입력에서 끌 수 있습니다.

## 단축키

`mod`는 macOS에서 ⌘, 그 외에는 Ctrl입니다. 명령 팔레트(`mod+Shift+P` 또는 F1)에서 명령을 검색할 수 있습니다. `mod+/`는 지금 쓰는 키(직접 바꾼 키 포함)와 고정 키를 묶음별로 보여 주는 **단축키 한눈에 보기**를 엽니다(검색 가능, "설정에서 바꾸기"로 설정 › 단축키로 이동, ADE 편집기 안에서는 Monaco의 줄 주석에 양보).

| 키 | 동작 |
|---|---|
| `mod+Alt+O` / `mod+Alt+W` | 프로젝트 열기 / 닫기 |
| `mod+Alt+1…9` | 프로젝트 선택 (9는 마지막) |
| `mod+Alt+]` / `mod+Alt+[` | 다음 / 이전 프로젝트 |
| `mod+Alt+B` | 사이드바 접기/펼치기 |
| `mod+Shift+T` | 새 터미널 탭 |
| `mod+Shift+N` | 새 탭에서 CLI 실행 선택 |
| `mod+Shift+W` / `mod+Alt+Shift+W` | 탭 / 포커스 pane 닫기 |
| `Alt+]` / `Alt+[` / `Alt+1…9` | 다음 / 이전 / N번째 탭 (9는 마지막) |
| `Ctrl+PageDown` / `Ctrl+PageUp` | 다음 / 이전 탭 |
| `Ctrl+D` / `Ctrl+Shift+D` | 좌우 / 상하 분할 (macOS도 Ctrl) |
| `mod+Shift+Enter` | pane 최대화 전환 |
| `Alt+Shift+]` / `Alt+Shift+[` | 다음 / 이전 pane 포커스 이동 (최대화 중이면 옮겨 간 pane이 최대화됨) |
| `Alt+Shift+1…9` | 이 탭의 N번째 pane으로 (왼쪽→오른쪽, 위→아래 순, 9는 마지막) |
| `mod+Alt+C` | 채팅 입력창으로 돌아가기 (이 탭에서 마지막으로 쓴 채팅, 없으면 프로젝트에서 가장 최근 채팅, 하나도 없으면 새 채팅을 열지 물음) |
| `Alt+0` | 사이드바의 현재 탭(분할이면 현재 pane) 줄로 포커스 |
| `mod+Alt+.` / `mod+Alt+,` | 다음 / 이전 확인 필요 탭·pane (질문·승인 대기 먼저, 그다음 응답 완료, 다른 프로젝트 포함) |
| `Ctrl+Tab` / `Ctrl+Shift+Tab` | 포커스된 편집기 그룹의 다음 / 이전 파일 (편집기에 포커스가 있을 때만, 그 밖에서는 키를 그대로 넘김) |
| `mod+/` | 단축키 한눈에 보기 |
| `Ctrl+Alt+←/→` | 채팅 입력창에서 이전 / 다음 모델 |
| `Ctrl+Alt+↑/↓` | 채팅 입력창에서 Effort 올리기 / 내리기 |
| `mod+Shift+G` / `mod+,` | Git 커밋 그래프 / 설정 |
| `mod+Alt+F` | 피드백 요청 패널 전환 |
| `mod+Alt+Shift+F` | 피드백용 화면 캡쳐 시작 |

터미널에 포커스가 있을 때 일반 Ctrl 조합은 기본적으로 셸·CLI로 전달하지만, 분할(Ctrl+D·Ctrl+Shift+D)과 Ctrl+PageUp/PageDown은 터미널에서도 앱 동작으로 실행합니다. 터미널에 ^D(EOF)를 보내려면 `Ctrl+Alt+D`(설정에서 변경) 또는 명령 팔레트의 "터미널에 ^D(EOF) 보내기"를 씁니다. 설정 > 단축키의 "터미널에서도" 체크로 키마다 앱이 가져갈지 셸에 줄지 고를 수 있습니다(`settings.termKeys`). Alt+W는 CLI 입력으로 남겨 둡니다. ADE 편집기(Monaco) 안에서는 Shift·Alt·⌘ 없는 `Ctrl+글자` 단축키를 앱이 가져가지 않고 편집기에 넘깁니다(예: `Ctrl+D`는 분할이 아니라 다음 일치 항목 선택). macOS에서는 채팅 입력창 같은 텍스트 칸에서도 `Ctrl+글자`가 macOS 편집 키(`Ctrl+D` 앞 글자 삭제, `Ctrl+A`/`Ctrl+E` 줄 처음/끝 등)로 남습니다. Windows의 채팅 입력창에서는 `Ctrl+D`가 그대로 분할입니다. 프로젝트가 하나도 열려 있지 않은 첫 화면에서도 명령 팔레트, 프로젝트 열기(폴더 선택), 설정, 피드백 요청·화면 캡쳐 단축키는 동작하고, 팔레트에는 그때 쓸 수 있는 명령만 나옵니다. (Windows PowerShell은 PSReadLine이 Ctrl+D를 기본으로 연결하지 않아, ADE 터미널이 시작할 때 `DeleteCharOrExit`로 연결합니다. 프로필이 이미 지정했다면 건드리지 않습니다.) 사용자가 설정에서 직접 지정한 단축키는 기본키보다 우선합니다.

### 키보드로 오가기

- **명령 팔레트**는 VS Code처럼 접두사로 찾을 대상을 고릅니다. 아무것도 없으면 명령과 모든 프로젝트의 탭·채팅·프로젝트를 함께(글자를 치면 설정 항목도), `>`는 명령만, `#`는 탭·채팅·프로젝트(에이전트와 상태 `응답 필요`·`확인 필요`·`작업 중` 표시), `@`는 프로젝트 파일(`files/list`, 고르면 ADE 편집기로 바로 열림), `,`는 설정 항목(그 섹션이 열린 설정 창), `?`는 접두사 목록입니다. 최근에 고른 항목이 먼저 나오고(이 창의 localStorage), 검색 중에도 비슷한 점수면 최근 항목이 위로 갑니다. 키가 있는 명령은 오른쪽에 키를 보여 줍니다.
- 팔레트의 모든 명령은 설정 › 단축키에서 키를 정할 수 있습니다. 기본 키가 없는 명령(탭 이름 바꾸기, 탭 위/아래로, pane 분리, 2×3 그리드, 크기 균등화, 브랜치 전환, 테마 전환, 둘러보기, 파일 트리, 오류 패널, 사용 기록, 변경 내역, 플러그인 설정, 파일 열기, pane을 다른 탭으로 옮기기, 탭 합치기, pane 맞바꾸기, 새 탭/오른쪽에서 에이전트 실행)은 `없음`으로 보이고, 정한 키는 되돌리기 버튼으로 지웁니다.
- **pane 옮기기**: "포커스된 pane을 다른 탭으로 옮기기…"는 대상 탭을 고르게 하고(pane이 하나뿐인 탭은 탭째 합침, "새 탭으로 분리"도 있음), "현재 탭을 다른 탭에 합치기…", "포커스된 pane을 다음 pane과 맞바꾸기"도 팔레트에 있습니다.
- **사이드바**는 Tab 한 번에 들어가는 트리입니다(지금 줄 하나만 Tab 정지점). `↑/↓` 줄 이동, `←/→` 프로젝트 접기·펼치기 또는 상위 줄/첫 하위 줄, `Home/End` 처음/마지막 줄, `Enter`/`Space` 선택, `F2`·`Delete`·`Alt+↑/↓`·`Shift+F10`은 그대로입니다. 줄 안의 X·＋ 버튼은 Tab으로 들르지 않습니다.
- **편집기 파일 탭**도 Tab 정지점 하나입니다. 탭 줄에서 `←/→`·`Home/End`로 파일을 바꾸고 `Delete`로 닫습니다. Tab으로 편집기에 들어가도 그 편집기가 포커스된 pane이 되어 pane 키·최대화가 그 편집기에 적용됩니다.
- pane을 옮기는 키(`Alt+Shift+]/[`, pane 번호, 채팅 키, 확인 필요 키, 팔레트의 탭 검색)는 실제 입력 포커스도 그 pane으로 옮깁니다(채팅 입력창, 터미널, 편집기, 새 창 목록 순). 최대화를 켜고 끌 때는 최대화했던 pane에 포커스가 남습니다.
- 크기 조절 막대(사이드바, 분할 경계, 오른쪽 패널, Git 패널)는 마우스를 올리면 더블클릭·클릭 동작을 툴팁으로 알려 주고, 포커스한 채 화살표로 크기를, `Enter`로 더블클릭(분할 경계는 클릭)과 같은 동작을, `Home`으로 기본 크기를 고릅니다.
- **창 밖 알림**: 질문·승인 대기나 응답 완료로 확인이 필요한 탭이 있으면 창 제목이 `(2) 무너에이드`처럼 바뀌고(작업 표시줄·Alt+Tab에 보임), 창이 뒤에 있을 때 개수가 늘면 Windows는 작업 표시줄 버튼을 깜빡이고 아이콘에 빨간 점을 붙이며, macOS는 Dock 배지와 한 번의 튕김으로 알립니다. 창으로 돌아오면 깜빡임이 멈춥니다. 설정 › AI 툴 › 공용 › 알림의 "창 제목과 작업 표시줄에 표시"(기본 켬)로 끕니다(`settings.attentionBadge`, 데스크톱 쪽은 `apps/desktop/src/attention.js`의 IPC `ade:attention`).

### 글자 편집

macOS의 키캡 `Delete`는 브라우저에서 `Backspace`이며, `Fn+Delete`는 앞으로 지우는 `Delete`입니다. Option은 Alt와 같은 키입니다.

| 키 | 터미널로 전달하는 동작/시퀀스 |
|---|---|
| `Cmd+←/→` | 줄 처음/끝 (`Ctrl+A/E`) |
| `Cmd+↑/↓` | 입력 처음/끝 (`Ctrl+Home/End`) |
| `Cmd+Shift+방향키` | Shift+Home/End 또는 Ctrl+Shift+Home/End |
| `Cmd+Delete` / `Cmd+Fn+Delete` | 줄 삭제 (`Ctrl+U`) / 커서 뒤 삭제 (`Ctrl+K`) |
| `Option+←/→` | 이전/다음 단어 (`Esc b/f`) |
| `Option+Delete` / `Option+Fn+Delete` | 이전/다음 단어 삭제 (`Esc DEL` / `Esc d`) |
| `Ctrl+Backspace` | 이전 단어 삭제 (`Ctrl+W`) |
| 방향키·Shift+방향키·Ctrl+방향키·Home·End·Delete | xterm의 일반/애플리케이션 모드 시퀀스 |
| `Tab` / `Shift+Tab` | 자동완성 / 역방향 Tab (`HT` / `Esc [Z`); Claude 작업 중 기존 후속 입력 큐는 유지 |
| `Shift+Enter` / `Alt+Enter` | CLI의 줄바꿈 (`Esc CR`) |

선택 영역, 여러 줄 이동, 삭제 범위는 실행 중인 셸·CLI의 키맵에 따릅니다. 예를 들어 기본 zsh의 Ctrl+U는 줄 전체를 지웁니다. Shift 선택을 지원하지 않는 CLI에 선택 기능을 강제로 추가하지는 않습니다. Option+문자의 Esc 접두 입력은 설정의 **Option 키를 Meta로 사용**을 켜면 사용할 수 있으며, 꺼 두면 특수 문자 입력을 유지합니다. 한글 등 IME 조합 중 편집키는 가로채지 않습니다.

채팅 입력창에서는 Shift/Option/Cmd+방향키를 브라우저의 글자 선택·이동에 사용합니다. 슬래시·파일 자동완성 목록이 열려 있어도 수식키가 붙은 방향키·Tab을 자동완성으로 처리하지 않습니다.

## 데이터와 복구

기본 경로는 [환경 변수](../ENVIRONMENT_VARIABLES.md)에 있습니다. 최근 프로젝트·화면 배치·설정과 터미널별 에이전트 세션 기록이 저장됩니다. 경로나 세션 정보가 들어 있으므로 데이터 폴더를 공유하지 마세요.

열린 프로젝트·공용 설정은 `app-state.json`, 최근 목록은 `recent.json`, 프로젝트별 레이아웃과 저장소 worktree 설정은 `<projectId>/state.json`입니다. 이전 버전이 만든 `<projectId>/runs/`(서버 SDK 실행 기록)는 더 이상 읽지 않으며 필요 없으면 지워도 됩니다.

창 새로고침은 기존 서버의 PTY에 다시 붙고 최근 터미널 출력 256 KiB를 재생합니다. 앱을 직접 종료했다가 다시 켜면 저장된 레이아웃에 새 셸을 열며 예전 셸 프로세스나 명령 실행을 복원하지 않습니다(Claude 대화는 `claude --resume`으로 이어집니다). 서버는 종료 직전에 각 Claude의 세션 ID를 한 번 더 기록합니다.

자동 업데이트의 재시작은 다릅니다. 터미널은 앱과 분리된 PTY 호스트 프로세스가 갖고 있어서, 업데이트로 앱과 서버가 내려가도 셸과 그 안의 명령·에이전트는 계속 실행됩니다. 새 버전의 서버가 같은 호스트에 다시 붙어 열려 있던 프로젝트의 터미널을 같은 ID로 넘겨받고, 그사이 출력은 호스트가 모아 둔 최근 256 KiB에서 재생합니다. 그래서 업데이터는 터미널 작업을 기다리지 않고, 재시작을 넘기지 못하는 작업(플러그인 세션 등)만 기다립니다.

Chat의 에이전트 CLI도 같은 호스트가 파이프 프로세스로 갖고 있습니다. 호스트는 CLI 출력을 줄 단위로 번호를 붙여 서버가 읽었다고 알릴 때까지 보관합니다. 서버가 정상적으로 내려갈 때(업데이트, dev reload, 백그라운드)는 각 채팅이 어디까지 읽었는지와 진행 중인 턴·승인 대기·백그라운드 작업을 채팅 폴더의 `live.json`에 남깁니다. 새 서버는 그 줄 다음부터 이어 읽으므로, 응답 중인 턴도 끊기지 않습니다. 채팅 로직은 서버에 있어 업데이트 즉시 새 버전이 적용됩니다. 서버가 비정상 종료되면 이어받지 않고 예전처럼 턴이 끊긴 것으로 표시합니다(세션 복구 가능).

앱 창의 X나 ⌘Q로 끌 때 터미널이나 채팅이 살아 있으면 `백그라운드로 남기기 / 종료 / 취소`를 묻습니다. 백그라운드로 남기면 앱과 서버만 끝나고, 호스트는 다음 실행이 붙을 때까지 기한 없이 터미널과 채팅을 유지합니다(받아 둔 업데이트는 그때 설치하지 않고 다음 종료로 미룹니다).

- 호스트는 설치 폴더 밖, `<userData>/pty-host/<내용 해시>/`의 복사본(Node 실행 파일, 호스트 소스, node-pty·ConPTY)에서 실행됩니다. 설치 폴더 파일을 잡고 있지 않으므로 Windows 업데이트의 폴더 교체가 막히지 않습니다. 내용이 같은 복사본은 다시 쓰고, 쓰지 않는 복사본은 다음 실행 때 지웁니다. 플러그인이 터미널에 넣는 도구도 이 복사본의 Node로 실행합니다.
- 앱은 호스트를 분리된 프로세스로 띄우고 `<userData>/pty-host/pty-host.json`(사용자만 읽을 수 있음)에 연결 정보를 남깁니다. 다음 실행은 이 파일로 살아 있는 호스트를 찾아 다시 씁니다.
- 수명: 앱을 직접 종료하면 터미널과 채팅도 끝납니다. 백그라운드로 남기면 기한 없이, 업데이트 재시작이면 5분, 앱이 비정상 종료되면 2분 동안 새 앱을 기다린 뒤 터미널을 정리합니다. 터미널도 연결된 서버도 없으면 바로 끝납니다. 기록은 `<userData>/pty-host/pty-host.log`에 남습니다.
- 앱과 호스트는 연결할 때 버전을 확인합니다. 새 앱이 이전 호스트와 맞지 않으면 그 터미널을 몰래 끄지 않고 새 호스트로 시작하며, 이전 터미널은 넘겨받지 못했고 몇 분 뒤 정리된다고 알립니다.
- 호스트를 띄우지 못하거나 실행 중에 호스트가 끝나면 이후 터미널과 채팅 CLI는 예전처럼 서버 프로세스 안에서 열리고, 이때는 업데이트가 그 작업을 다시 기다립니다. 파이프 프로세스를 모르는 이전 호스트(업데이트 직후 한 번)도 채팅은 서버 안에서 열고, 백그라운드는 그 호스트의 최대 30분까지만 유지합니다.

ADE의 Claude Code/Codex 실행 메뉴와 터미널에 직접 입력한 `claude`·`codex` 모두 각각의 대화 ID로 복구합니다. bash/zsh/sh/dash/fish/PowerShell에서 사용자 시작 설정을 먼저 읽고 ADE 셸에만 실행 함수를 연결합니다. 셸 히스토리는 비어 시작하지 않도록 따로 맞춥니다(`terminal-sessions.js`). zsh는 macOS의 `/etc/zshrc`가 세션 폴더(`ZDOTDIR`)를 기준으로 `HISTFILE`을 정해 위쪽 화살표 기록과 자동완성이 비던 것을, 사용자 `.zshrc`를 읽기 전에 사용자 `ZDOTDIR`(없으면 홈)의 `.zsh_history`로 되돌려 막습니다. 사용자가 `HISTFILE`을 직접 정했다면 그 값이 남습니다. PowerShell은 PSReadLine 2.1 이상에서 히스토리 예측이 꺼져(`None`) 있을 때만 `History`로 켭니다. 프로젝트 데이터의 `terminal-sessions/<terminalId>/`에 Claude의 `SessionStart` 훅 기록 또는 Codex의 터미널별 실행 로그를 보관합니다. Claude의 `/clear`·`/resume`, Codex의 새 대화·복구로 ID가 바뀌면 다음 복구에 반영합니다. ID가 없는 기존 기록은 `claude --resume` / `codex resume` 선택 화면을 엽니다. 최근 대화를 임의로 선택하지 않습니다.

Codex는 다른 터미널과 기록이 섞이지 않도록 이 실행에만 `--no-daemon`과 `log_dir`를 지정합니다. 세션 추적은 Codex 0.163.0의 root session 시작 로그 형식과 Claude 2.1.304의 `SessionStart` 훅을 기준으로 합니다. Codex는 `--no-daemon`을 지원해야 하며, 로그 형식이 바뀌거나 Claude 훅이 비활성화되어 ID를 확인하지 못하면 자동 복구 대신 선택 화면이 필요합니다. 전역 CLI 설정 파일은 변경하지 않습니다.

절대 경로·`command claude`·`env codex` 등으로 함수를 우회하거나, SSH/중첩 셸·tmux에서 실행하면 ID 추적이 보장되지 않습니다. 지원하지 않는 셸도 직접 실행 추적 대상이 아닙니다. 업데이트 전에 이미 열린 셸에는 함수가 없으므로 새 터미널에서 실행하세요.

프로젝트당 터미널 32개, 전체 128개 제한이 있습니다. 파일 감시 실패 시 서버는 계속 동작하며 현재 프로젝트의 Git 상태를 설정한 Diff 새로고침 주기(기본 3초)로 비교합니다. 백그라운드 프로젝트는 다시 선택할 때 갱신합니다.

터미널에 붙여 넣은 이미지는 데이터 폴더의 `paste/`에 저장되며 24시간 뒤 또는 전체 256 MiB를 넘으면 오래된 것부터 지웁니다.

## Worktree와 안전 범위

공유 경로가 기본입니다. 멀티 저장소 프로젝트에서 저장소별로 worktree를 명시적으로 켤 때만 생성합니다. 원본 통합은 fast-forward만 지원하고, dirty 상태의 제거와 대상 경로의 변경을 거절합니다. 통합 전에 터미널에서 변경을 커밋하세요. 브랜치는 자동 삭제하지 않습니다.

로컬 서버가 실행한 Git은 저장소의 fsmonitor와 hooks를 끕니다. 터미널에서 직접 실행하는 Git과 에이전트 CLI의 Git은 사용자의 환경을 따릅니다. 프로젝트 루트 경로 검사는 터미널과 에이전트를 격리하지 않습니다. [보안 제한](SECURITY_REVIEW.md)을 참고하세요.
